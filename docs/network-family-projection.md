# 已验证地址族：范围与请求检查的统一接线

2026-09-08。修复的是生产接线缺项，不表示当前网络已取得单族证明或可以启用严格模式。

此前即使资格准备器已经合法声明某个 origin 只可 IPv4，默认操作范围仍生成 IPv4/IPv6 两个目标，请求检查也默认检查两族；两边没有消费准备后的地址族结论。因此合法单族资格仍会被要求提供未使用的 IPv6 许可。

现在 `NetworkRuntime.resolveFamilies` 由同一个主进程回调供操作范围和每次请求检查使用。回调仅接收账号身份、上下文和精确 origin，不接收 Session、URL path/query 或凭据。未提供解析器仍要求双族；提供后返回 null、空数组、重复或非法值、异常一律拒绝，不回落 IPv4或双族。原 `resolveTarget` 保留为受控测试接缝，不能与新解析器同时配置。

请求返回的族集合必须与此前提交的该 origin 的范围完全相同。地址族变化先撤销旧许可，重新声明范围并经过两轮新证据才可运行，不能在请求时悄悄缩小已经批准的范围。同步撤销、更换账号上下文或递归声明不能写回旧范围。

生产回调接 `ProductionProofRuntime.resolveAddressFamilies(origin)`，只使用已有来源实例。它不选择配置、不读文件、不发起 DNS/HTTP、不隐式准备。默认组件检查当前候选仍有效且与原资格的来源、文件、策略和 Direct 策略匹配；原资格必须来自当前生命周期及内存审查。独立缓存的 `PathConformanceAdapter` 完整检查原关联、映射、期限和当前 Chromium 启动约束，再返回精确已审核 origin 的族数组副本。它从未开始异步路由读取，不依赖首次 collect，避免“没有范围就不能 collect、没有 collect 就没有族解析”的循环。

前后还会核对原资格身份、选择来源、设置实例、Gate 版本与同步重入。审查撤回或当前来源失效时通知拥有者闭闩并撤销来源。未知 origin 只返回 null，不因此丢弃其它账号仍有效的资格。getter 的结果是范围输入，所有这些族仍各自需要真正的目标/规则/TLS/DNS/大陆出口许可。

主入口已经接入此回调：observe 保留原未知双族模型；strict 只接受来源投影。正式 enforcement 仍为 observe，真实完整审查及启动准备窗口仍未提供。无资格时强改 strict 会闭闩，不会借这项接线获得默认允许。

## 本轮网络审核留下的边界

[当前正常解析政策只读审核](./network-normal-resolver-policy-review.md)确认：六个未解释条目不匹配三个固定目标，但过滤模式缺失，且物理网卡仍存在 IPv4 与 IPv6 DNS 库存。库存不是实际解析选择的证明，也不能据此排除正常业务的 IPv6 分支。

旧强制 AAAA 实验改变了诊断上下文，它否定 `ipv6=false` 对任意 Chromium 路径的普遍限制，不能直接证明原业务上下文必须永久双族。首期仍需实际正常解析/hosts/启动上下文的有限符合性证据；若确实可用两族，则各自验证。Windows 原生 IPv6 不必有 mihomo 连接 ID，但必须取得原请求 socket、实际物理源/目的路由及同类大陆出口证据。当前尚不能生成单族或完整双族资格。
