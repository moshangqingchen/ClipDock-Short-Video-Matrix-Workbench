# fake-IP 请求与内核目的地址的对应

本模块补充阶段 2 的路径事实，正式应用仍为观察模式。Chromium 连接 fake-IP、内核实际连接真实地址是两层不同读数，不能要求两者地址集合相等，也不能只因目标规则为 DIRECT 就认定二者已经对应。

`anonymous-request-socket.ts` 有界解析隔离匿名工厂的 NetLog。它从固定 `/robots.txt` 请求出发，沿请求与连接依赖取得唯一 TCP 四元组；不启动日志、识别 Windows 进程或签发许可。共享解析、代理和证书服务按实际 source 类型隔离；请求本地的代理解析或证书事件只过滤相关服务边，不删除整个 socket/controller。多个请求、多个候选连接、重定向、来源类型冲突或缺失时拒绝。输出不保留 Cookie、请求头、原始 URL、证书或正文。

`resolver-flow-mapping.ts` 将这个四元组与同次实际观测组合：

- 已选加载方式、原始配置关联、系统网络与 hosts 输入。
- Windows 读取的具体应用进程身份及相同 TCP 四元组。
- 请求前不存在、请求后出现的本次 mihomo 入站连接，核对源地址、源端口、目标、TCP、DIRECT、开始时间和可用的进程身份。
- 当前配置明确的 fake-IP 范围，以及同次内核 DNS 原始答案中的真实目的地址。DNS 原期限必须覆盖实际发送到收到响应头；后验检查不刷新该期限。

构造出的原对象只留主进程内存。JSON 或对象复制不恢复其原始配置关联；后续适用性检查仍核对新一轮配置、内核、系统网络、hosts、目标范围和真实 DNS 截止。资格审核完成时间与请求发生时间分开：后验可以较晚完成，不能倒填审核时间或让已过期的当前输入继续用于请求。

当前只接受匿名 TLS 工厂的固定 robots 请求，以及同族 fake-IP 到真实地址的样本。它不把样本族变成业务单族约束，不把 robots 请求冒充出口回显，不证明物理 socket 或大陆出口。`PathConformanceAdapter` 保留独立的物理路径记录与工厂适用性要求；缺项仍返回不可验证。原来的真实地址解析分支继续要求两个实际地址集合一致。

2026-09-08 07:00 的首次完整公网实验发出了一次匿名请求并收到响应头，随后旧版解析器返回 `SOCKET_AMBIGUOUS`。该结果未取得完整后验映射，未签发许可；其原始结果已保留。07:07 的本机 TLS 实验确认 socket、连接任务和 controller 均可能自带证书／解析／代理事件；修复后的解析器和裁剪日志离线重放通过。未知来源节点作为关联桥的反例也已修复，解析器共 29 项测试通过。

07:10:21–07:10:27 的新公网复验独立通过 15 项检查：一次匿名 robots 请求得到 200，实际工厂、唯一请求图、Windows 应用四元组、本次 mihomo 流和 fake-IP 到真实 IPv4 的对应均完成；内核实际目的地址同时属于当轮前后 A 答案。前读的 1 秒 TTL 覆盖发送至响应头与紧随的读取，末次后验时已过期则如实保留；后读较长 TTL 来自本次真实新答案。来源、内核、系统网络和 hosts 前后稳定，23 个生产源哈希稳定。详见 [隔离实测](./network-fake-ip-flow-observation.md)。

该公网结果证明本次实际对应，尚未组装或安装生产 `RetainedPathQualification`，也不是所有可能地址族、工厂等价或大陆出口验收；`qualificationGranted` 与 `permitIssued` 仍为 false。单个 robots 样本不能使其它目标或账号上线。

NetLog 原始记录只可在没有账号业务流量的隔离实验或明确安静窗口中采集，不能把默认元数据模式理解为天然不含隐私。字段保留及输出范围应按 [Electron NetLog 文档](https://www.electronjs.org/docs/latest/api/net-log) 校验。
