# 当前证据组合来源：实现与安装条件

本文记录 `src/main/network/production-proof-source.ts` 与 `route-applicability.ts`，不修改已冻结的严格分流规格。

**组合实现已完成；主入口已接来源生命周期门面，但真实路径一致性记录的生产者仍未完成，正式运行仍是观察模式。** 门面在 observe 明确拒绝证据；严格分支没有实际资格时不会调用组合采样。单元测试中的合格记录只用于验证组合逻辑，不是本机大陆出口或平台流程的验收结果。接线详见 [来源生命周期](./network-proof-source-runtime.md)。

## 一轮实际组合

1. 检查真实操作目录、目标范围和 Gate 当前代际。首版支持已审核的 HTTPS/TCP 操作；WSS 明确不可验证。
2. 读取当前控制器，先检查模式、版本、内置 `DIRECT` 的实际类型和 dialer。明确非 DIRECT 提前拒绝；依赖目的 IP 阶段的未决规则允许继续读取同轮输入，但仍须在匿名 HTTP 前完成全部决定。未检查的别名不猜成代理或直连；global 拒绝，rule + TUN 不因此被拒绝。
3. 通过 `PathInputReader` 取得同轮配置、内核生命周期、Windows 网络、DNS 与候选目标查路。核对真实读取时间、全部目标和代际。
4. 从主进程可信来源取得当前适用的传输、DNS、地址族与物理路径记录。记录必须绑定输入样本、配置来源与版本、内核、Windows 网络及账号上下文；缺失就停止。依赖匹配阶段的规则共用 `CurrentRuleContextSet`：账号/TLS/出口工厂分别核对目标、传输配置与实际 TCP，所有可能分支均须命中同一真实 DIRECT 终点；缺少任一上下文不得退回简单规则解释器。
5. `verifyRouteApplicability()` 核对目标与回显端点的实际 Direct 策略、各候选地址的物理路线及保留的路径资格记录。TUN 接口不是物理出口证据；未知或 fake-IP 地址必须有当前映射及查路来源。多个候选地址不能只挑其中一条合格路线。
6. 经独立匿名工厂取得公开 TLS 与出口观察。相同 origin 合并 TLS；同族目标只有属于同一已验证物理路由类别才可共享出口样本。
7. 再读当前规则与 Direct 策略。可信来源须把每个诊断样本的原始路径与当前目标逐项关联，核对真实工厂、诊断 Session 上下文、样本摘要、原始时间、地址族、路由类别和资格来源。关联的异步等待结束后重验原规则上下文集合，不用新集合给旧样本延寿。所有中间及最终证据受所用上下文最短期限约束。
8. 全部条件成立才构造已有 `LiveRuleEvidence` 与 `DirectEvidenceBatch`，交给现有 Issuer/Gate。source 不直接给账号亮灯；两轮新证据、期限和撤销继续由原有门闩处理。

## 原始样本与当前适用性

`factoryId` 识别采样器的生产初始化契约，`transportContextId` 保留本次独立 Session 身份。二者相同或同属 Electron 都不自动证明与账号路径相同。

`DiagnosticSamplePathBinding` 分开保留原始路径记录和本轮适用性核对。响应正文中的 IP 地址族不冒充 socket 地址族；若已有真实 socket 族且与出口报告矛盾，拒绝。未知 socket 族不能凭空补值：必须有已验证的路径约束或经实测审核的路径等价依据，且当前依赖仍相符。TLS 一个 origin 覆盖两个地址族也受此要求约束。

出口刷新与最长年龄分别沿用 60s、120s 出发默认值。缓存按代际、规则版本、内核、Windows 网络、实际 Direct 策略、地址族、物理路由类别和出口工厂路径身份分组；每轮重新核对当前配置、有效策略和路径适用性。配置文件变化不能跳过重核，也不要求所有可安全复用的旧样本无条件重新拨号。复用时原始观测时间和原始路径记录保持不变；新核对时间不是新出口采样时间。整轮成功后才入缓存，撤销清空缓存。

DNS 比较和候选期限按操作声明的 host + 地址族计算。`KernelDnsReader` 保留运行内核原始答案、TTL 与真实候选上限；无关地址族的一秒 TTL 不阻断已经有单族约束的范围。旧来源未提供上限时沿用其保守整体截止，不推算一个新的 15 秒期限。默认操作仍须覆盖所有可能地址族，这项优化不创造 IPv4 约束。

## 可信来源仍须提供的实测事实

| 记录 | 必须来自的事实 |
|---|---|
| 当前配置与路径资格 | 实际加载来源、当前规则/geo 数据、内核生命周期和实际路径契约，不能仅把配置候选改名为已验证 |
| 传输兼容 | 账号、匿名 TLS、出口诊断的实际进程/网络服务路径与已审核工厂配置 |
| DNS 与地址族 | 实际解析路径、fake-IP 映射及所有可能地址族；单族范围需要独立约束依据 |
| 物理路由类别 | 当前目标与回显候选的真实出站、接口和地址族，以及保留的资格样本 |
| 样本关联 | 原始诊断连接或已审核约束/等价依据，加上本轮依赖匹配；不能仅填几个非空 evidenceId |

记录接口只允许主进程内部依赖注入。校验器能发现缺失、错配和期限问题，不能把输入字符串变成外部事实。主入口的资格提供者仍缺省，不把合成记录或历史 JSON 报告作为默认来源；实际资格完成前不能签发正式业务许可。

不新增“每目标公网回显”“每轮 socket 取证”或“完整内核源码身份”的要求。阶段 2 通过实测冻结适用的规则/路径范围，解释不了就保持不可验证；不能用永久空实现宣称严格模式已完成。

## 验证边界

`production-proof-source.test.ts` 的 106 项测试中，合格用例经过真实 `verifyRouteApplicability`、`createLiveRuleEvidence`、`validateDirectEvidence` 和 Gate 两轮；覆盖错配、期限、取消、缓存原始记录及失败不缓存。调用者和依赖之间保留独立输入快照，内外异步返回之间再次核对撤销、销毁和版本。`route-applicability.test.ts` 的 75 项测试单独验证真实地址与 TUN/fake-IP 投影的差异，并统一拒绝各类 IPv4 映射地址拼写。这些都是受控模块测试，不能替代真实 mihomo 出口、六平台登录/验证码/轮询或生产并发验收。

当前环境的只读预检另见 `network-production-source-preflight.md`。该实验即使通过拒绝断言，也只说明真实规则前置检查生效，不是可签发许可证的结论。
