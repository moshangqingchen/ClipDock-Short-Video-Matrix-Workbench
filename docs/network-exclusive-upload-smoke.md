# 互斥网络模式：受控上传撤销验收

**HTTP/1.1 首轮与 HTTP/2 最终轮均通过 18 项检查。** 实际 Electron 43.3.0 / Chromium 150.0.7871.212 中，主进程上传和页面 XHR 在已发送部分正文时收到模拟代理开启事件，生产租约立即撤销，原上传连接／页面关闭；接收端最终收到的字节均小于声明的 32 MiB。闭闩后新增的三个上传入口没有到达接收端。

这是一项本机传输验收：代理状态、大陆可达结果和 OS 指纹均为合成输入。没有切换真实猫猫云、TUN、系统代理或系统 DNS；没有真实账号、平台上传或公网请求。它不证明物理零包，也不替代用户真实开关切换后的验收。

## 覆盖的生产路径与隔离

实际加载 `ExclusiveNetworkSwitch`、`NetworkRuntime`、SessionGuard 所在的 `session-observer`、`gatedSessionFetch`、业务租约及 `closeAccountView`。两个合成代理关闭／大陆可达轮次通过后，才授予本次隔离会话业务资格；服务器已收部分上传后，调用生产 `observeProxyEnabled(0)` 撤销资格。

每个通过轮次分别执行一次主进程 `gatedSessionFetch` POST、一次真实页面 XHR POST，每次固定 **33,554,432 字节（32 MiB）**。服务器核对请求声明长度和合成 Cookie，累计实际 `data` 字节；达到 256 KiB 阈值后暂停读取，并检查计数在撤销前的 50 ms 内稳定。H2 分块会越过阈值，故实际暂停点不强行写成恰好 256 KiB。

独立临时 userData/sessionData 和非持久会话不包含真实登录态。TLS 服务器只监听 loopback；测试域名只在此 Electron 子进程映射到 loopback，并使用该 Session 的精确测试证书指纹校验，没有全局忽略证书错误。H2 服务器拒绝 H1，接收端实际版本分别为 `1.1` 和 `2.0`。

XHR 的原生 `executeJavaScript` 调用在启动发送后即返回；不把文档销毁后可能悬挂的长脚本 Promise 当作传输收尾。上传终态由真实页面销毁、生产连接清理和接收端事件共同核验。

## 实际接收字节与缓冲边界

下表取 H1 首轮及 H2 最终轮。所有上传声明长度均为 33,554,432 字节。

| 协议／入口  | 暂停及撤销时已读字节 | 生产清理后最终已读字节 | 撤销后继续读出的字节 |
| ----------- | -------------------: | ---------------------: | -------------------: |
| H1 主进程   |              262,144 |                950,272 |              688,128 |
| H1 页面 XHR |              262,144 |                966,656 |              704,512 |
| H2 主进程   |              278,375 |                278,375 |                    0 |
| H2 页面 XHR |              278,375 |                360,285 |               81,910 |

撤销后恢复接收端读取，用于累计背压期间及关闭过程已经进入传输缓冲的数据。**这些增量不能称为零泄漏窗口，也不能据此区分每个字节是在撤销前还是撤销后上网卡。** 通过条件是原租约撤销、上传被取消、实际传输关闭、正文未收全，并且生产清理后再等待 150 ms 时累计字节不再增加。测试自己的强制 socket 清理在这些检查之后，不能用于凑出撤销通过结果。

## 两次 H2 失败的原因与修正

首轮 H2 主进程只收到 278,375 字节，已经出现 `aborted=true`、请求／连接／流关闭及 `RST=8`，但 `complete=true` 导致旧断言失败。第二轮主进程通过，XHR 收到 360,285 字节且同样取消关闭，却因 `ended=true` 再次被旧断言拒绝。两次失败均保留为失败，没有回写成通过。

Electron 43.3.0 的 [DEPS](https://raw.githubusercontent.com/electron/electron/v43.3.0/DEPS) 指定 Node 24.18.1，最终实际报告也记录该 Node 版本。对应 [HTTP/2 兼容实现](https://github.com/nodejs/node/blob/v24.18.1/lib/internal/http2/compat.js#L327) 的 `complete` getter 会在 aborted、readableEnded、closed 或 stream destroyed 任一条件成立时返回 true；它不表示正文已完整收到。另一处 [onStreamCloseRequest](https://github.com/nodejs/node/blob/v24.18.1/lib/internal/http2/compat.js#L269) 在关闭时调用 `req.push(null)`，因此取消后的兼容可读流也可能发出 `end`。

修正后的两种协议共同要求：声明长度等于固定总长，实际累计字节大于零且小于声明长度，发生取消，请求及实际传输均已关闭。H1 继续要求 `complete=false`、`ended=false`；H2 要求流已关闭且 `RST=NGHTTP2_CANCEL（8）`，原 `complete`、`ended` 仍照实记录。最终 H2 的 XHR 仍为 `complete=true`、`ended=true`，没有靠重复运行等待这两个字段碰巧为 false。

这与此前 [HTTP/2 运行时冒烟](network-runtime-http2-smoke.md) 已记录的兼容流 EOF 边界一致。本轮修正仅涉及验收脚本，没有修改生产取消逻辑。

## 新请求阻断、收尾与结论范围

两个通过轮次均验证：闭闩时 `gatedSessionFetch` 新上传直接返回休眠；原始 `session.fetch` 新上传被请求钩子取消；新页面 XHR 失败。`closed-main`、`closed-raw`、`closed-xhr` 均为接收端零到达；越界请求计数为零，实际上传均只含合成凭据。

每轮结束时原生待完成工作、窗口、WebContents、自有 socket、H2 session、请求和响应对象均为零；报告 `cleanup.drained=true`，父进程看门狗未触发，临时目录已移除。两个通过轮次退出码为零；两次失败也完成了清理，但退出码为 1，未把清理成功当成验收成功。

四次记录各自包含 18 个生产来源文件及脚本／bundle 摘要，均核对该次运行前后来源稳定。协议断言修正使脚本摘要发生变化，具体摘要以各自 JSON 为准；H1 首轮没有被描述成最终脚本的一次新增复跑。

本项完成的是**互斥模式下，受控 H1/H2 上传中途撤销及闭闩后禁止新上传**的有限验收。它不覆盖平台上传协议、断点续传、自动发布、QUIC、真实 OS 开关效果或物理零包。真实网络状态保持原样。
