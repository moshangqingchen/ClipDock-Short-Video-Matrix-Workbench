# YouTube 可恢复上传：实现与验收边界

2026-09-08。YouTube 官方上传已接入现有主进程代理、账号、凭据和持久任务体系，国际账号仍没有 Chromium 分区。国内／代理互斥策略保持不变。本轮没有切换实际系统代理或 TUN，没有使用真实开发者应用、平台 Token 或真实视频做出网试验。

## 使用入口

在“国际账号”配置 Google 桌面 OAuth 应用后，点击账号的“授权视频上传”。普通读取授权不会自行增加写入权限；只有用户明确选择上传授权时才追加 `youtube.upload`，授权响应缺少该范围便拒绝保存成功状态。应用配置、本地账号记录和代理模式都不代表已取得授权。

选择素材库视频，填写标题和描述，明确选择是否专为儿童制作、是否包含需要披露的逼真合成或修改内容，再提交。默认私密、默认不通知订阅者；用户主动选择公开后，按钮显示“上传并请求公开到 YouTube”。首期界面类别为人物与博客（22），没有动态类别目录。标题最多 100 字符，描述最多 5,000 UTF-8 字节；这不是本地视频内容合规或编码检查。

开发者应用未通过审核时，平台可能将上传限制为私密；界面使用官方返回的实际可见性，不能将用户申请的 public 当成已公开。[官方上传接口](https://developers.google.com/youtube/v3/docs/videos/insert)

界面仅读取本地账号、素材和任务记录，不自动上传或查询平台。提交立即返回持久任务 ID；同账号、素材、授权和规范化元数据的活动提交合并，改变可见性等元数据时不能覆盖原任务。TikTok 与 YouTube 共用一个上传工作槽，各账号任务及授权身份独立；代理不合格时等待，不回落直连。

## 请求与恢复

初始化固定为 `POST https://www.googleapis.com/upload/youtube/v3/videos`，带 resumable 类型、snippet/status 和显式元数据。服务端返回的 Location 必须匹配已实现的精确目标契约：HTTPS、`www.googleapis.com`、固定上传路径、唯一 uploadType/upload_id/part，以及可选 notifySubscribers。未知主机、额外参数、重定向和异常结构拒绝；尚未声称兼容所有可能的 Google 上传地址。

上传地址只在主进程加密保存，并绑定账号、任务和授权版本。每个 PUT 还需要主进程持有的目标许可及实际 CONNECT/TLS 网络证据。renderer 只能传素材 ID 和有限元数据，不能传路径、URL、请求头或 Token。YouTube 的 PUT 按官方协议使用 Bearer；TikTok 签名 PUT 不带 Bearer，两者不能混用。

文件大小上限为代码中的 256 × 1024³ 字节；支持素材库已有的 MP4、MOV、WebM、M4V、MKV、AVI、FLV、WMV 引用。上传前固定文件句柄、核对完整 SHA-256，分片发送时再次校验，变化立即停止。没有复制、转码、内容分析或本地编码／时长检查；大文件的完整摘要计算需要时间。

采用 8 MiB 固定分片，最后一片取余量。服务器 308 的 Range 从第零字节计数；恢复先对原 URL 发送空 PUT 查询，再从实际确认位置继续，允许位置落在旧分片内部。文件读取会验证跨越的原始摘要块。缺失 Range 表示尚未确认字节，不猜“上一片应该成功”。服务端进度回退、超出已发送范围或结构异常时停止。[官方可恢复上传协议](https://developers.google.com/youtube/v3/guides/using_resumable_upload_protocol)

308 和可重试错误中的 Retry-After 会参与等待；等待期限及连续失败次数保存在 SQLite，重启和手动检查不能提前重发。传输错误采用至少 30 秒、指数增长到 300 秒的本地等待，服务端要求更久则遵守，最多 8 次连续失败／无进度后停止。超过 24 小时或无法解析的 Retry-After 不猜测。上传 URL 的 24 小时是本地上限，不保证服务器保留这么久；服务端提前返回过期就停止。不会自动创建新的上传替代过期或结果未知的初始化。

每个上传请求最多 120 秒，同一真实代理隧道持续更新短网络证据；上传不延长证据 TTL。网络变化、取消或授权失效会撤销操作，清理完成才释放槽位。关闭窗口保留任务；取消只停止本机，不删除平台内容。取消后的“查询结果”只查状态，绝不重新传文件。更换应用／授权、断开本机授权或删除账号的旧回调不能继续写入。

## 结果与数据库

取得创建响应中的视频 ID 后，加密记录保留该 ID，随后从固定 videos.list 查询该视频的频道身份、实际可见性与处理状态。传输结束、处理完成、公开是不同状态。未列出与私密视频处理完成显示 ready；只有确认处理完成且实际 public 才显示 published。处理中保持等待；处理信息消失时显示待核对，不伪报视频失败。相互矛盾的已处理／处理中回应不会标为公开。[官方视频资源](https://developers.google.com/youtube/v3/docs/videos)

每轮状态核对起始间隔 30 秒，收到终态停止；同次运行连续 60 次仍未确定则交给用户核对，重启会重置这个内存计数。网络状态仍只在内存，重启 checking；任务及等待时间持久化不代表网络资格持久化。

迁移 11 原样保留版本 10 的任务和凭据密文，新增 waiting-retry、ready 以及主进程私有的等待期限／尝试次数。重建期间不触发上传秘密删除，恢复每账号活动任务唯一约束和删除级联。任务、签名 URL、Token 均不进入 BackupPayload；公开 DTO 和现有审计不含 URL、Token 或文件绝对路径。不同 Windows 用户／电脑无法解密时保留旧密文，但不能承诺恢复旧上传。
