## 已接入桌面程序

“国际账号”页面经独立 preload／IPC 管理 YouTube、TikTok、X 的账号记录。创建默认未授权，可列出、创建、删除、清除本机授权，并主动开始或取消官方授权；renderer 不能直接写授权状态或远端身份。国际 UUID 不能进入国内视图，国内账号列表、六平台 collector 和发布助手不共用这些记录。

`global_accounts` 独立存储公开账号信息，没有 `partition`、Token、Cookie 或网络状态列。删除账号与清理其 OAuth 密文使用同一事务。现有国内备份导出及 replace 均不触碰国际记录和凭据。

页面提供“官方授权”和流程中的“取消授权”；TikTok 另有“授权草稿上传”，YouTube 另有“授权视频上传”。点击后由主进程核对官方应用、加密能力和当前代理证据；仅打开页面不会启动授权，代理开启也不会使账号显示已授权或运行。授权状态事件经过安全字段投影，只留在内存；浏览器预览拒绝真实授权。已授权记录可手动读取平台数据或取消，打开页面只取本机快照。[TikTok 草稿](global-tiktok-draft-delivery.md)和[YouTube 可恢复上传](global-youtube-upload-delivery.md)及其持久任务已接入；X 写入和远端撤销仍待完成。

历史打包检查曾验证三个合成账号经 preload 创建后可见、当时的授权占位按钮禁用、国内视图拒绝且无浏览分区目录，随后全部删除。该一次性数据目录中的旧检查不等于当前真实 OAuth 验收。

按用户“还没有，先完成本机配置入口”的要求，国际账号和设置页面均已接入开发者应用配置面板。支持 Client ID／Client Key、回调端口和按平台要求填写应用密钥；未申请时可保持未配置。公共配置进入 `global_apps`，应用密钥以 `oauth_client_secret` 进入系统加密凭据表。配置读取只有公共字段和密钥元数据，没有原值读取 IPC，输入框保存、失败、关闭和卸载时清空。详见[本机填写说明](global-app-setup.md)。

迁移 5 在数据库层隔离国内／国际账号 UUID（忽略大小写），防止国内备份导入相同 ID 后误开国际记录的分区；发现历史冲突时回滚迁移，不删除任何账号。迁移 6 新增公共应用表；迁移 7 扩展凭据种类并原样保留既有密文。应用身份、端口或密钥变更时，同一事务删除该平台旧 Token 并要求已有授权账号重新授权；保存或清除失败完整回滚，其他平台不受影响。通用凭据 IPC 不允许修改这两类 OAuth 凭据，国内备份不包含国际配置和秘密。

迁移 8 新增 `global_read_snapshots`，只保存资料、指标、最多 20 条作品及实际抓取时间，不含远程媒体 URL、原响应、Token 或网络状态。账号删除级联清理；读取时核对当前授权、平台与远端身份。保存和 `GlobalRead` 审计在同一事务，撤销或静默写入失败会回滚，旧结果不伪装为新快照。

## 已实现并接入授权路径的模块

- `src/main/api/proxy-transport.ts`：Node HTTPS 只经显式 HTTP CONNECT；精确平台 API host 白名单，拒绝重定向、Cookie 和代理认证头进入目标请求。缺少隧道授权回调时不创建连接；匿名 CONNECT 成功仍必须通过实际 socket 上下文的授权回调，才能握手和发送业务头／正文。有效期、撤销信号、响应及请求大小、并发上限贯穿传输，结束等待真实连接清理，不回落直连。
- `src/main/api/oauth-flow.ts`：系统浏览器授权流程所需的主进程事务管理，包含随机 state、PKCE、仅绑定 127.0.0.1 的单次回调、账号／平台／代际绑定、超时及取消。兑换与保存必须显式注入，没有默认 fetch。兑换迟到不保存，完成结果不含 Token。
- `src/main/api/global-token-store.ts`：验证 OAuth 事务身份与 Token envelope 的账号、平台一致，并保留已知远端身份。系统加密密文、账号授权标记、安全 OAuthEvent 审计在同一个同步 SQLite 事务提交；保存前、中、后复核事务有效性，失败回滚。Token 类型和读取接口只在主进程，不进 shared、IPC 或备份；跨 Windows 用户／电脑解密失败保留密文。
- `src/main/api/global-read-service.ts`：串行处理每账号的手动读取，复核代理资格、账号和配置；需要时组合 Token 刷新与原版本核验提交，然后调用官方读取适配器并保存快照。取消、配置变化和退出保持真实工作收尾，迟到结果不能更新本机数据。

当前 TikTok profile 只申请 `user.info.basic`。统计和作品列表分别缺少 `user.info.stats`、`video.list`，对应能力显示 `scope_required` 并跳过请求；本轮没有扩大 scopes。YouTube、X 也按 Token 实际授权及平台权限、额度处理，不能把 OAuth 成功写成所有读取能力可用。

OAuth profile 有明确平台差异：[Google 原生应用](https://developers.google.com/identity/protocols/oauth2/native-app)、[X 授权码流程](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)使用 S256 base64url；[TikTok Desktop Login Kit](https://developers.tiktok.com/docs/en/login-kit-desktop)当前要求 SHA-256 hex。回调端口须符合各开发者平台登记规则，不能把动态端口支持当成三平台统一保证。

正式入口已通过 `GlobalOAuthService` 组合这些模块，经 `GlobalProxyRuntime` 检查当前代理条件并提供实际传输，官方兑换器也已接入。没有默认客户端 ID 或伪造代理许可；证据不足时在主进程拒绝。代码及受控测试完成不等于真实官方 API 已上线，当前仍缺真实代理验收和官方开发者应用下的账号授权验证。
