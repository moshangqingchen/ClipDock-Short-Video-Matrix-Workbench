# 1.0.6-rc.8

修复 1.0.6-rc.7 中大量账号在正常使用时变成“待核实”的回归。原逻辑将主页确认保存在内存中，五分钟后、Cookie 更新或重启时删除；后台检查又只读取已经打开的主页，导致未退出的账号长期无法重新确认。

## 登录状态

- 仍以抖音、快手、小红书、B 站主页的当前账号状态为依据，不使用创作者后台登录、Cookie 存在或历史状态文案代替主页确认。
- 明确的主页登录/未登录结果与原观察时间保存在本地；五分钟表示需要复核，不表示自动退出。普通导航、Cookie 轮换、页面加载和网络失败保留上次明确结论，不虚构新的确认时间。
- 主页明确未登录会更新为未登录；验证页、账号环境重置和替换恢复会撤销旧证据。
- 无主页确认记录的旧账号在空闲时自动检查。复核只使用本账号原有分区，一次加载主页，不刷新现有主页、不重试获取二维码；同账号失败后五分钟内不再自动加载。
- 自动复核不覆盖可见页面、消息、扫码、验证、编辑或正在执行的采集任务。检查使用的临时页面会在完成后释放；被用户或其他任务接管的页面保留。网络暂停时等待恢复。
- 修复后台页面实际视口为 0 像素、主页头像因此不渲染的问题。复核期间使用隐藏宿主提供 1280×800 的实际视口，保持原账号页面和会话，结束后恢复；检查页面静音且不会弹出窗口。
- 等待页面加载结束并在 Cookie 更新后重新读取稳定的主页结果，避免登录信息加载期间误丢弃有效确认。等待有上限，不重复刷新主页。
- B 站顶部当前账号的个人空间链接和头像共同确认登录，支持未设置头像的账号；默认头像不再造成待核实，也不会作为自定义头像导入。游客头像、页面作者和隐藏控件仍不作为当前账号登录证据。
- 确实没有取得主页结果时仍会显示待核实，不强制将账号显示为在线。悬停状态可查看本次检查原因和上次确认时间。

## 验证

- 分批回归 5,102 项通过：主批次 191 文件、5,061 项，独立 OAuth 流程 41 项。自动主页检查与视图池的 87 项、主页解析及登录检测的 238 项回归另行复核通过。
- 类型检查、ESLint、生产构建及 NSIS 安装包生成通过。
- 最终安装包使用隔离临时数据通过 Electron 启动、账号边界、凭据加密、消息入口与布局、数据观测及全局平台既有功能检查；未向真实联系人发送消息。
- 原生 Electron 视口测试复现修复前宽度为 0、页头不可见，验证修复后实际为 1280×800、页头正常显示；全程窗口隐藏，只创建一个网页实例，使用独立临时目录和内置测试页。
- 针对性回归覆盖持久证据的重启读取、Cookie 轮换、五分钟后状态保留、明确退出覆盖旧结论、账号环境重置、网络撤销后的迟到结果、自动主页复核限流，以及消息/编辑保护与临时页面回收。
