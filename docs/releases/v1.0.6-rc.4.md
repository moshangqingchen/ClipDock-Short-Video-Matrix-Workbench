# 1.0.6-rc.4

本次预发布更新改善账号登录、作品采集与历史恢复，并统一窗口、托盘和安装程序图标。浏览器分区与历史数据沿用原目录，数据库升级前创建一致恢复点。

## 登录稳定性

- 修复预发布版本 User-Agent 清理遗漏：带 `-rc`、`-beta` 或 `+build` 的应用版本不再残留在浏览器标识中，保留实际 Chromium 引擎版本。
- 普通账号切换复用现有页面；隐藏公众主页有回收宽限，减少对正在使用的页面的干扰。
- 按官方静态依赖链补充抖音登录与安全组件的精确资源主机，沿用原有导航范围和 DIRECT 路由验证。[资源范围及出处](../douyin-login-resource-scope.md)
- 二维码诊断被动记录已有请求的业务码、有限状态和环境一致性结果，不发起额外登录请求，不记录二维码 token、Cookie、设备标识值或完整请求头。
- 保活遇到采集冷却时延期执行；跳过或未确认的检查不再视为保活成功，并采用有界退避。视频号隐藏的安全管理页面可重新获取官方身份证据，可见、编辑和验证流程受到保护。
- Cookie 持久化保留 host-only 等作用域属性，等待异步保存，传播失败和超时结果，并在退出前写盘。

抖音扫码问题在修复浏览器标识后获得用户“可以进入”的复测反馈；这不代表平台永不要求重新验证。视频号真实隔夜登录仍需单独验收。

## 数据采集与恢复

- 六平台作品采集支持页码或游标，逐页保存进度、去重记录、暂停与退避状态；异常分页不能误报完整。
- 缺失指标保留旧值，真实 0 和真实下降照常记录；区分官方账号指标与已采作品合计，显示字段来源和更新时间。
- 历史补采、取消与重启恢复使用持久化任务队列，尊重平台限流并避让正在编辑的页面。
- 增加经营分析的存储、队列与界面基础，保留统计日期、单位、币种和可用状态。各平台开关默认关闭；当前只读取官方页面明确呈现的区间，不承诺已补齐 90 天数据。
- 数据库迁移新增恢复点；备份格式 4 支持新指标与经营记录，兼容旧备份并避免旧值覆盖新数据。

详细实现与尚待完成的平台验收见[采集质量说明](../collection-quality-1.0.6-rc.1.md)。

## 资源与仓库维护

- 窗口、托盘、渲染界面和 Windows 安装包共用新图标资源；移除被替代的旧托盘图标模块与生成脚本。
- 仓库仅包含源码、测试、构建资源、维护脚本与技术文档。原始诊断、临时截图、安装产物、账号数据和本机备份不纳入版本控制。
- 更新前后本机数据核对通过。公开说明不包含账号标识、本机绝对路径或真实数据快照。

## 验证

上传前全量回归通过：183 个测试文件、4,823 项测试。移除无引用的旧指标汇总函数并修正日期注释后，相关 6 个文件、33 项测试再次通过；最终类型检查、ESLint 和生产构建通过。隔离临时数据的安装包启动烟测、浏览器标识与二维码观察器专项回归此前已通过。

```powershell
npm run typecheck
npm run lint
npm test -- --maxWorkers=1 --no-file-parallelism
npm run build
```

安装包测试覆盖窗口、原生账号视图与 IPC，不代替各平台真实登录及后台数据完整性验收。
