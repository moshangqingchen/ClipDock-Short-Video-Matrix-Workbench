# TikTok 草稿上传：实现与验收边界

2026-09-08。本轮接入 TikTok 官方 FILE_UPLOAD 草稿流程，目标是送到用户的 TikTok 收件箱，随后由用户编辑并确认发布。没有 Direct Post、网页投稿自动化或自动点击发布。国内继续执行互斥网络策略；本轮没有切换用户的系统代理、TUN，也没有使用真实账号、开发者应用或平台 Token 做上传实验。

## 使用入口

在“国际账号”中保存 TikTok 开发者应用配置，点击该账号的“授权草稿上传”，再从素材库选择视频或导入视频，点击“上传到 TikTok 收件箱”。普通“官方授权”仍只申请基本资料；草稿按钮明确追加 `video.upload`。应用及用户必须实际授予上传范围，配置保存、代理开启和返回授权页面都不代表权限已取得。[官方草稿初始化接口](https://developers.tiktok.com/doc/content-posting-api-reference-upload-video)

打开页面只读取本机素材、快照和任务记录，不自动授权、查询平台或上传。提交立即返回任务 ID。只有代理模式且来源证据合格时，主进程队列才开始执行；国内模式或不可验证时保留任务、停止发送，不回落直连。每账号最多一个活动上传，全局一个上传工作槽。相同账号、素材和授权的活动提交会合并；更换视频需等待或取消原任务。

支持素材库中 MP4、MOV、WebM 的文件引用，代码上限为 4 × 1024³ 字节。先打开固定文件句柄、核对大小和完整 SHA-256；每个分片发送前重查文件信息和分片摘要，文件变化立即停止。不会复制、转码或自动修改原视频。当前没有本地编码、帧率、尺寸及时长检测，平台可能拒绝不满足要求的视频，最终限制以官方处理为准。

## 传输与续传

初始化固定使用 `open.tiktokapis.com/v2/post/publish/inbox/video/init/`。8 MiB 基准分片，小文件一次发送，余量合入最后一片，单片小于 16 MiB，按序传输。仅正确的中间／最终响应才更新已确认字节数；传完后进入“等待 TikTok 处理”。[媒体传输协议](https://developers.tiktok.com/docs/en/content-posting-api-media-transfer-guide)

签名上传地址只能来自已验证的官方初始化响应，或与当前账号、任务和授权版本匹配的加密记录。首期精确接纳官方文档示例中的 `open-upload.tiktokapis.com`、`upload.us.tiktokapis.com`，路径 `/video/`，唯一的 `upload_id` 与 `upload_token` 参数。其他返回地址拒绝并报告，不能声称已适配所有地区的上传集群，更不能动态扩大白名单或跟随重定向。

签名 URL 和 publish ID 作为 `upload_session` 密文保存在凭据表，不进入任务 DTO、审计或备份。传输还需主进程拥有的不可复制许可；renderer 不能传 URL、路径、上传令牌或范围。PUT 只带内容类型、分片范围及由传输层计算的内容长度，不带 OAuth Authorization 或 Cookie。初始化和状态查询的 OAuth 请求只去固定 API 主机。

每次请求仍需实际 CONNECT socket、内核归属、非 DIRECT 链及当期代理出口证据。上传请求总期限最多 120 秒，短网络证据按[同一隧道续证](global-proxy-tunnel.md)更新，不因上传延长证据 TTL。超时、撤销或证明失效关闭实际连接；清理未完成前不释放真正的工作槽。上传 URL 按初始化开始时间保守计一小时，不延长服务端有效期。

重启或分片回应不确定时，必须先查询原 publish ID 的官方状态。只有远端确认字节数不小于本机已确认值，并且恰好落在原分片边界，才读取原文件继续。未知、缺失、回退或片中进度停止发送，不猜测、不重新初始化。初始化已发出但结果未保存时标为“结果待核对”，不会自动创建第二次上传。

“取消上传任务”只停止本机发送，不能删除已送达平台的内容。用户主动查询已取消任务时，只查状态，绝不恢复传文件。更换应用、重新授权、断开本机授权或删除账号，都会取消相关在途任务；旧回调受授权绑定和任务 revision 检查，不能复活任务。断开本机授权及更换应用会删除相关加密上传地址；普通解密失败不擅自删除密文。

## 状态、存储与界面

| 官方结果／本机阶段 | 显示与行为 |
| --- | --- |
| 尚无代理资格 | 等待有效代理，保留任务 |
| 文件已获传输响应 | 视频已传完，等待 TikTok 处理 |
| `SEND_TO_USER_INBOX` | 已送达收件箱，待用户编辑和发布 |
| `PUBLISH_COMPLETE` | TikTok 确认用户已完成发布 |
| `FAILED` | 上传未完成；显示固定原因，不透传原响应 |
| 状态／进度无法确认 | 结果待核对，不自动重复创建上传 |

状态查询固定使用官方 status/fetch。自动查询间隔起始值 30 秒，收到收件箱或终态后停止；同次运行连续 60 次仍在处理则交由用户查询，重启会重置这个内存计数。任务队列持续保存在 SQLite；网络资格和页面状态不持久化。上述等待状态都不会修改国内登录态。[官方状态接口](https://developers.tiktok.com/doc/content-posting-api-reference-get-video-status)

迁移 10 原样复制已有凭据密文，增加 `upload_session` 种类及 `global_upload_jobs`。每次任务状态修改递增 revision，并与现有 `UploadAttempt` 审计同事务写入、读回核验。只保留每账号最多 20 条终态历史及活动任务，界面最多展示 20 条；删除任务级联清除上传密文。备份仍是显式业务 schema，上传任务和凭据根本不在 BackupPayload 中。便携目录跨电脑或 Windows 用户迁移后可能无法解密，需重新配置应用和授权，旧上传不能承诺续传。

## 已验证与尚未验证

受控检查覆盖：独立上传授权、缺范围拒绝、立即入队／合并、关闭代理不取证、完整文件及分片变化拒绝、初始化不确定不重试、真实 SQLite 关闭重开后的原任务续传、查询取消任务不重发、迟到结果、换授权、删除／断开清理，以及凭据／备份／IPC／界面隔离。

本机 TLS 接收端测试走真实 Node CONNECT 与 TLS，使用仅测试 worker 信任的合成证书；覆盖签名 PUT、固定目的、无 OAuth 头、凭证标记不可复制、取消及错误 TLS 身份。它没有使用平台服务器，不能替代真实 TikTok 上传、应用审核、地区域名、视频格式及系统代理切换验收。18:12 全量 127 文件／3838 项、typecheck、lint、打包通过；18:15 新包隔离桌面检查退出 0，界面截图已查看。完整结果及原始失败记录见[当前交付记录](network-exclusive-delivery.md)。
