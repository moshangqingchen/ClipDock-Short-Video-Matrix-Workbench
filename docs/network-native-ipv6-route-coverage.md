# 本机 IPv6 路由覆盖：本轮只读库存

本轮读取表明：当前与 global-unicast 目的空间相交的 IPv6 路由全部属于物理接口 12，具备继续实现有限路由政策覆盖的实际基础。但不能把这个结论扩大成“全部 IPv6 都由已验证的物理出口覆盖”，也不能直接把旧单个 socket 的资格应用到所有源地址。应用仍为 **observe**；本轮没有签发许可、改动网络配置或启用严格执法。

## 采样来源与边界

- 采样时间：2026-09-08 03:15:14.223 UTC（北京时间 11:15:14.223）。同一临时 Node 进程的单调时间窗口为 21.0567–1724.4721 ms，耗时 1703.4154 ms。
- 一个隐藏、无交互的 PowerShell 进程连续读取两次 `ActiveStore` 的 IPv6 路由、接口和地址，并读取适配器基本身份及 IPv6 临时地址设置。固定命令为 `Get-NetRoute`、`Get-NetIPInterface`、`Get-NetIPAddress`、`Get-NetAdapter -IncludeHidden`、`Get-NetIPv6Protocol`；前三者明确限定 IPv6，未调用 `Find-NetRoute`。
- 子进程限制为 7 秒、384 KiB 输出、每类最多 1024 条。没有 HTTP、DNS 查询、账户会话或配置写入。
- 两次库存分别按表排序后计算摘要，前后相同：`3a5d989f21cd9f23824e6b07efbb1082abe4b48dbc75d0a26c7fd336f8de50ec`。这是本次库存摘要，不是生产网络指纹格式。
- 原始地址只参与临时内存计算，没有写入报告或文件。原始结构未另存 JSON；本记录依据当时工具的脱敏输出，不能恢复原始对象、关联品牌或历史资格。本轮没有采集内核 owner、控制器或配置来源的新一轮关联。

库存共有 32 条 IPv6 路由、9 个 IPv6 接口、14 条 IPv6 地址及 14 个适配器基本记录。所有路由当时均为 `Alive`、路由 metric 为 256；两次库存一致只说明该短窗口内稳定。

| 本机所在 global-unicast on-link 前缀 | 1 | 接口 12，前缀长 64，下一跳为 on-link | 与远端默认网关路径不同，必须单独处理 |
| 本机 global-unicast 地址的本地路由 | 6 | 接口 12，前缀长 128，`Local` | 本机目的地址不能视为已验证公网出口 |
| link-local | 14 | 接口 75、8、51、22、9、15、12 各有一条 /64 和一条 /128 | 包含当前活动的非物理接口，未被公网物理类覆盖 |
| multicast | 9 | 接口 59、75、8、51、22、9、15、12、1 | 不是普通 TCP 公网目的，不计入公网覆盖结论 |
| loopback | 1 | 接口 1，/128 | 本地路径，未被公网物理类覆盖 |

标准 global-unicast 范围内没有发现接口 12 之外的竞争路由；相关的 8 条记录正是默认路由、本地 /64 和六条 /128。接口 12 当时为 `Hardware=true`、`Up`、`Connected`；接口 59、51、75 为活动的非物理接口。接口 1 的 IP 接口记录为 `Connected`，但本次适配器表没有对应行，不能将其解释成已确认断开。

本轮没有 ULA 专用路由或其他 special 专用路由。**没有专用路由不等于不可达**：默认路由仍可能匹配，实际源地址、scope 和 TCP 行为尚未验证。ULA、link-local、loopback、本地 on-link/本机地址及其他 special 分支不能因此借用远端公网证明；IPv4-mapped 也不能冒充原生 IPv6 类。DNS 可能返回这些地址，不能只假设它返回 global-unicast。

## 对有限覆盖分支的裁定

本轮可以分析的有限集合是：**排除本机 on-link /64、本机地址及 special 分支后的远端 global-unicast 目的空间**。库存中这部分只有接口 12 的默认路由，没有观察到另一条更具体的物理或 TUN 路由。这个事实使“普通 DNS 返回不同公网地址，但仍落入同一已审核物理路由政策”的实现方向值得继续，不能要求 DNS 答案数组永远等于内核 DNS 候选才有讨论空间。

现有精确路由类绑定了源地址、目的路由前缀、下一跳和 metric。同一接口换用另一条 Preferred 源地址，或者目的地址命中本地 /64、/128，都会改变这些事实。故旧的精确源地址／前缀类不能直接复用；有限政策分支需要保留已验证样本，并明确它覆盖的源地址选择集合和目的范围，不能仅删除原有比较条件。

同 /64、同物理接口及当前地址状态是审核源地址策略的材料，**本轮库存本身不证明该分组所有地址均已验证为大陆出口**。地址新增、临时地址轮换、状态变化或路由变化都必须撤销相应覆盖。现有生产指纹也不能被描述成已经观察了本次采集的全部源地址状态及临时地址设置。

本轮结果只收窄了下一实现的可行范围：远端 global-unicast 有明确实际库存支撑；特殊目的和源地址选择仍需明确覆盖或拒绝。没有新建 producer，没有扩大已授权配置修改范围，普通 DNS 与物理路径的生产关联尚未完成。
