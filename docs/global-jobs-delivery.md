# 国际读取任务：等待代理与重启恢复

2026-09-08。国际账号的主动读取已改为持久化任务。点击“读取数据”后立即返回任务 ID；代理尚未合格时显示“等待代理”，可取消，离开页面不再取消任务。此轮只交付读取队列，上传／草稿／发布不在该队列中，也没有真实平台业务验收。

## 运行方式

- 主进程 `GlobalJobQueue` 使用独立的 `global_jobs` 表，不进入国内 `cn_jobs` 或 Chromium 分区。同一账号至多一项活动读取，重复点击合并；每账号保留至多 20 项终态历史和一项活动任务，IPC 最多返回 20 项，活动任务优先。
- 启动、重启、挂起和网络撤销都保持等待。数据库保存的是用户意图，没有网络许可、出口证据或已允许状态。`AccountNetworkState` 仍不进入渲染层持久化。
- 当前系统代理／TUN 必须被确认为开启，才允许尝试国际取证。它只是前置条件；真正执行仍由 `GlobalReadService → GlobalProxyRuntime → ProxyTransport` 获取有效资格，并对每个实际目标／隧道检查。未知、代理关闭、路径失联均不能发带 Token 的请求。
- 只有一个工作槽，按入队顺序选择已到重试时间的任务，前一项实际工作收尾后至少间隔 1 秒。单项无法取得代理证据时，按 30、60、120、240、300 秒退避，后续上限 300 秒；该任务等待时其他平台可执行，避免一个不合格目标长期挡住整队。许可有效期和原证明模型没有放宽。
- 权限、额度、身份或业务响应错误终止本次任务并显示固定原因；不会无休止重试平台 API。任务执行成功后停止，不变成平台定时采集；只有用户已提交且尚未完成的读取会恢复。

## 撤销与身份

迁移 9 新增 `global_jobs`，并为国际账号增加主进程私有的 `grant_revision`。它表示一轮用户授权身份，不是出网资格，也不进入 `GlobalAccount` 的 IPC 数据。原 v8 密文不变；已有授权分配版本，新官方授权重新分配，正常 Token 轮换保持不变。

任务绑定账号、平台、远端身份、授权版本、公共应用配置和加密应用密钥的版本摘要。绑定只在主进程／数据库使用，渲染层没有读取接口。清除授权、删除账号、修改开发者应用或密钥、重新发起授权前，先取消相应任务。即使下一次授权得到同一账号和相同 Token，旧任务也不能继续；正常刷新 Token 不会误取消任务。

每次执行、异步恢复、刷新提交和快照保存都复核任务版本及原身份。取消先撤销进行中的读取，再持久化终态；状态更新采用版本比较，旧回调不能把已取消任务改回运行／完成。公开取消可先返回，真正 HTTP／取证工作未结束时工作槽仍被占用，下一项不会偷跑。持久化取消失败会停止当前进程的队列并报错，不假装已经取消。

网络撤销保留任务为 `waiting-proxy`，不写账号离线，也不触发国内掉线通知。退出等待实际读取收尾。重启仅恢复等待的用户意图，再次验证网络和授权；没有保存“上次允许”的捷径。

只读任务允许安全重读：若进程在官方响应后、任务完成写入前退出，恢复可能再次读取。这里不承诺官方请求 exactly-once，不能把此恢复策略直接用到上传或发布。国内助手仍须人工确认，恢复不自动重新挂文件。

## IPC、界面与审计

`globalRead.get(accountId)` 仅读取本机快照。原直接 `refresh`／按账号 `cancel` 的 IPC 已移除；写入意图统一经 `globalJobs.submit(accountId)`，查询经 `list(accountId)`，取消经 `cancel(jobId)`。预加载对回复和事件二次验证显式 schema，仅传 UUID、平台、任务状态、时间、次数和固定错误。没有 Token、原响应、URL、绑定摘要或代理秘密。

页面订阅任务事件，迟到的旧版本和已卸载页面不能更新显示；取消后的旧完成事件不会触发快照回读。任务成功才读取新的本机快照。页面跳转只解除订阅，用户意图继续保留。所有队列状态来自主进程，没有 localStorage／zustand persist。

`GlobalJob` 事件写入现有 `audit_events`，与相应任务写入处于同一 SQLite 事务。审计只记录任务 ID、类型、状态、版本和固定错误。新表、授权版本和凭据均不进入现有业务备份；没有更改备份为整库导出。
