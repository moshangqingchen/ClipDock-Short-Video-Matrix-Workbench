# 国外网页登录与可选 API：最新产品调整

## 22:52 最终验证

国外账号侧栏刷新与窗口事件已做版本保护，旧状态不会覆盖新的休眠/打开状态；删除账号后窗口统计会立即归零。进入页面后自动选中第一个海外账号，只呈现对应平台官网工作区，不自动打开浏览器；删除或切换账号不会复用旧状态。最终全量 138 个测试文件／4084 项、typecheck、lint、打包和 `--packaged` Electron 冒烟通过。最新包哈希以[互斥切换交付记录](network-exclusive-delivery.md)为准。

代理证据过期/不可读时继续保持国内闭闩；代理撤销会关闭国外官网窗口；重复打开等待清理屏障；删除账号会清除官网工作区。最终包和 138 个测试文件／4081 项回归均已复验。

## 22:02 最终接线更新

国外账号树已与国内布局保持同构，`App` 路由会保留国外侧边栏；选中账号后显示平台专属官网工作区。代理资格撤销会同步关闭国外官网窗口，删除账号会清理选中工作区；窗口统计使用“窗口”而不是“在线”，不把 Chrome 已打开误报为平台已登录。最终全量回归 138 个文件／4081 项通过，打包和 `--packaged` Electron 冒烟通过。

## 21:18 更新：国外页面按国内工作台方式组织

国外账号现在使用与国内相同的工作台骨架：左侧为独立的“国外账号列表”，按 YouTube、TikTok、X 分组，支持搜索、展开／收起、数量统计和账号选中；右侧为选中账号的官网工作区，显示对应平台的固定入口。登录动作仍由对应平台官网完成，API 授权状态不会冒充网页登录成功。

添加国外账号不要求开发者应用。点击“打开官网”后，主进程先检查该平台入口目标的代理许可，再启动只属于该账号的 Chrome 目录；代理资格撤销会立即关闭代理连接并停止浏览器窗口的后续出网。国内账号仍使用原来的 Chromium 分区和工作区，两套账号目录不会互相复用。

本轮的真实本机验证包括：工作台创建的 Chrome 进程可启动和关闭、账号目录 Cookie 隔离与重开保留、在途请求撤销、代理关闭后不回落直连，以及 mihomo 当前配置下三个国外入口的匿名连接核验。没有使用真实平台账号、Cookie、OAuth Token，也没有切换系统代理或 TUN。X／TikTok 某次连续连接续证仍有短时失败，保持 fail-closed，待完成续证稳定性验证后再把“国外窗口可运行”扩展为长期在线承诺。

2026-09-08，用户明确将国外账号调整为“网页登录用于日常运营，官方 API 作为可选增强”，并要求国内／国外分类。该决定优先于旧方案中的“国际平台仅 API”。现有 API 代码、加密凭据、读取和上传任务保留，后续优先完成网页账号环境，不继续把开发者应用当作基本账号管理的前提。

## 本轮已经落地

- 主导航分为“国内平台”和“国外平台”。国内保留抖音、快手、小红书、B 站、百家号、视频号。
- 国外页面默认进入“网页登录”分类视图，可按 YouTube、TikTok、X 筛选账号；新建记录不要求 API 配置。
- “官方 API（可选）”由用户主动打开；原应用配置、OAuth、资料和上传工具仍可使用，打开分类页不挂载这些工具，也不发起 API 查询或授权。
- 国外页隐藏国内账号树，国内账号快捷键不误跳入国内工作区；新增账号快捷键聚焦国外表单。
- 网页登录入口已经接入：选中账号后显示对应平台的官网工作区，“打开官网”由主进程启动该账号专属 Chrome 环境；真实平台登录仍由用户在官网完成。已有 API 授权不能显示为网页登录成功。

## 历史实现记录（19:58 及以前）

以下条目记录接线前的实验边界，保留用于追溯；当前状态以本页 22:09 更新和最新打包记录为准。

19:58 更新（历史）：网页 CONNECT 传输及本地代理入口已完成 51 项受控测试；当时实际网页取证、浏览器进程管理和打开官网 IPC 尚待接线，随后已在 21:18 完成接入。详见[本轮代码与实验范围](global-web-transport.md)。

网页方式不要求开发者应用，但仍受“代理开时国外可运行，代理关时国外休眠”的严格互斥约束；代理开启本身不是网络许可。不能用 `shell.openExternal` 启动日常默认浏览器就宣称已隔离或受控。

优先使用标准 Chrome 的独立用户目录，必要时适配 Edge，不复用个人浏览器 Profile。当前本机有 Chrome 152.0.7977.76、Edge 152.0.4191.66；Chrome 的临时目录隔离已做受控实验，Edge 尚未启动或测试。浏览器网页状态、API 授权和网络资格分别管理；不复制浏览器 Cookie 到 API，不从 API Token 推断网页登录态。

Google 的政策禁止将应用 OAuth 授权导向开发者控制的内嵌浏览器。该条不能被扩大成“所有普通网页登录都已证明不可用”；YouTube 普通登录兼容性仍需实测。维持标准浏览器用户操作，不注入授权脚本或规避限制。[Google OAuth 政策](https://developers.google.com/identity/protocols/oauth2/policies)

网页流量必须经主进程管理的代理通路，并对实际连接继续执行短证据、撤销和不回落直连。标准浏览器的显式代理、DNS、QUIC、WebRTC、后台连接和退出清理需要受控接收端实验；命令行参数不是已验证出口保证。现有 API 的有限主机策略不能直接扩大给任意网页，应独立审核网页目标及登录／验证码／CDN。

先完成无账号、合成 Cookie 的浏览器隔离和网络取消试验，再装配真实网页登录入口。真实账号扫码和其他平台登录依然由用户操作，软件不自动发布。本次调整没有授权改变当前系统代理或 TUN，用户此前暂缓的整机网络切换继续保持。
