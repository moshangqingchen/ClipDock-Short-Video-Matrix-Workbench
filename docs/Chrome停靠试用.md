# Chrome 停靠试用

国外账号工作区新增「Chrome 试用」。点击后关闭该账号当前的 Electron 官网视图，用电脑上已安装的 Google Chrome 打开官方入口，将 Chrome 停靠在软件官网区域；顶部可「切回内置浏览器」。本轮为试用适配，默认添加账号流程保持原有方式。

## 实现与数据

- 使用未修改的 Chrome 程序，保留原生地址栏、标签页和用户输入。采用 Windows owner window 关系及位置同步；它仍是原生 Chrome 进程，并非可以替换 Electron 内核的 Chrome 组件。
- 每个账号使用应用数据目录内独立的 `global-browser-profiles/<账号ID>`。首次使用需要重新登录。现有 Electron 登录目录、日常 Chrome 配置和其他账号数据不迁移、不复制 Cookie。
- 专用 Chrome 启动时禁用扩展，避免机器级注册的「迅雷下载支持」等扩展确认弹窗遮挡登录；不修改系统注册表或日常 Chrome 的扩展设置。
- 只有用户点击试用才启动 Chrome；沿用代理开启才能使用国外平台的条件。代理撤销、关闭账号或退出应用时关闭对应 Chrome，优先正常关闭，必要时结束该账号所属 Job 中的进程；退出后检查目录占用再释放锁。
- Windows helper 只由主进程调用，浏览器程序路径、目录和官网入口由主进程决定，不接收渲染层任意程序、URL 或脚本。没有 Chrome 调试端口、网页脚本注入或密码读取。
- 软件主页、管理、上传、发布等入口向同一 Chrome 账号环境打开官网链接。YouTube 频道专属入口只从原生地址栏识别合法频道路径；识别不到时提示从官网操作，不编造频道地址。

## 验证与限制

2026-09-10 后续：已增加当前官方数据页面的网页观测，利用 Windows 辅助功能树读取非输入字段文本，详情见[国外网页数据观测](./国外网页数据观测.md)。不再仅限于读取地址栏；仍不接触密码或 Cookie，也没有 Chrome 调试端口与 Chrome 网页脚本注入。

已经在临时账号目录中实际启动 Chrome，观察 Google 登录页及本地测试页，检查内容区域定位、1080 窄窗口跟随、隐藏和恢复、两个独立账号的打开及进程退出、目录锁释放。试用按钮、IPC 和代理生命周期有针对性测试。

Windows 自动化工具对跨进程停靠窗口的输入目标识别不可靠，因此尚未确认键盘/输入法在用户实际操作中的完整表现，也未验证 Google 登录成功。用户需要在试用版中亲自输入并登录。Google 是否接受登录由平台决定，不能承诺不出现账号验证或风控。

[Google 对受支持浏览器的说明](https://support.google.com/accounts/answer/7675428?hl=en)指出内嵌环境可能被拒绝。[Chromium 独立用户数据目录说明](https://www.chromium.org/developers/creating-and-using-profiles/)说明了通过 `--user-data-dir` 分隔浏览器数据的机制。
