# ClipDock 严格分流方案（合并定稿）

适用仓库：ClipDock-Short-Video-Matrix-Workbench。规划日期：2026-09-07。

本文合并原主稿与代码评审，作为后续改造规格。当前仅交付计划，不表示功能已经实现、实验已经通过或网络已经受保护。

## 0. 产品决定

国内六个平台保留现有 Chromium 账号分区。只有当前目标的直连证据合格时，工作台才允许相关业务出网；未知、过期、失联或不匹配时拒绝并等待国内网络。代理能打开国内站，不构成放行理由。

网络执法全部放在 Electron 主进程；不另做 Windows 助手 exe，不承诺绕过 mihomo TUN。阶段 1—3 单独完成国内交付。国际平台是后续独立里程碑，走官方 API 和主进程 ProxyTransport，不进入国内账号分区。

冻结三项原则：

- 主进程统一执法，保留国内分区和既有工作台。
- 不可验证就休眠，国内不回落代理，国际 API 不回落直连。
- 国际能力后置，新增秘密只进入主进程凭据库，不进入备份。

## 1. 承诺、边界与非目标

### 1.1 本程序承诺什么

严格模式采用 fail-closed：在每个受控业务入口和每次请求检查时，没有适用于该目标、该网络路径、当前配置版本且未过期的许可，就不主动发出请求。

从启动开始默认关闭。发现证据失效后，立即关闭请求门闩、撤销任务许可并执行在途取消。对已关闭的门闩，不允许发送一条带登录态的请求去试路，不允许用代理重试。

### 1.2 允许运行的环境

首期支持可读、可解释的 mihomo 规则模式：当前实际目标匹配 DIRECT，相关出口证据指向中国大陆，且其他检查合格，可以运行。TUN 开启本身不等于不合格；规则模式与 global 模式必须分开判断。内核 direct 模式只有经过同样的路径验证并列入支持范围后才可运行。

global 模式按本产品首期政策保持国内休眠。Clash API 不可读、规则无法解释、目标未知或出口证据不足，同样休眠。没有 Clash 的可信直连环境可以后续增加独立证明适配器，但不能用“没有检测到 Clash”替代证明。

### 1.3 不作物理零窗口保证

本程序读取规则、批准请求与实际数据出网之间，外部程序仍可能修改 TUN 或系统路由。周期查询、事件订阅和请求钩子不能让这些步骤与外部内核原子执行。

因此验收承诺是“本程序按有效的目标证据执法，证据不合格时不发，发现变化后撤销”，不是“外部任意改路由时整机物理零包”。独立记录外部变化至发现、发现至关闭、关闭至取消完成的时间，不把检测窗口隐去。

不要求安装自有 TUN 驱动才能运行。若未来需要外部任意切换下仍绝对零跨境，则必须另立受控路由强制约束项目，不能继续用观察模型宣称已经满足。

### 1.4 不做

- 不强绑物理网卡承诺绕过 TUN，不提供强制国内上线或代理补发按钮。
- 不自动点击平台发布、不打码、不伪装指纹、不做代理池。
- 不把国际网页塞入 AccountWorkspace，不用网页私有接口替代未获授权的官方 API。
- 不承诺平台免审核、免验证码，也不推断 Cookie 绑定某个 IP 或重扫能消除平台历史。
- 不控制用户自行使用的系统浏览器、手机或其他程序；工作台不能自动借它们绕过拒绝。

## 2. 保留现有底座

国内平台固定为：抖音、快手、小红书、B 站、百家号、微信视频号。

保留每账号 persist:sv-account-<uuid> 分区、Cookie 持久化守卫、Chrome UA、导航白名单、视图池、zod IPC、SQLite 数据、AES 备份容器、平台数据解析逻辑、素材库和人工发布助手。

共享请求包装、会话取得方式、状态流和调度控制需要调整；“保留 collector”指保留平台解析行为，不代表 pageFetch 和异常处理完全不动。

当前创建 schema 已拒绝国际 id。此次拆类型是预防未来扩展导致国内入口被放宽，不将尚不存在的国际创建漏洞写成仓库现状。

当前仓库锁定 Electron 43.3.0。旧文档中的 9 文件／47 测试是历史基线；实施开始时重新记录实际测试数与结果，新增测试后不要求数量保持不变。本次文档整理未运行测试和真实账号网络实验。

## 3. 主进程模块与类型边界

~~~text
React 主界面
  四态、账号网络状态、等待任务、脱敏日志、公共设置
        │ 现有受校验 IPC
Electron 主进程
  NetworkObserver / ClashReader / DiagnosticTransport
        ↓
  DirectProof → EgressGate（唯一许可和撤销来源）
        ├─ AccountSessionRegistry → SessionGuard
        ├─ BusinessGate / GatedSessionFetch
        ├─ CollectScheduler / 国内任务队列
        ├─ PublishService
        └─ Audit
  CredentialVault
  ProxyTransport / OAuth / GlobalAccount（阶段 4—5）
~~~

新增模块规划位于主进程 network/ 和 security/ 内，不增加本地 RPC 服务。

国内链路统一使用 CnPlatformId：Account、创建输入、平台注册表、view、collector、探测、备份账号 schema 和仓储边界均保持国内限定。

GlobalPlatformId 可以先声明为 youtube、tiktok、x。阶段 1 不把现有 PlatformId 原地扩宽并传播到国内代码；可保留国内兼容别名，通用联合仅在确有跨组展示需要时另定义。

GlobalAccount 后续使用独立表和 IPC，无 partition 字段。view* 接收账号 UUID，取出账号后验证国内类型；不能通过国际 UUID、错误数据或备份导入进入国内浏览栈。

## 4. 网络观察与 DirectProof

### 4.1 观察结果和放行资格分离

NetworkSnapshot 保存诊断结果；RouteDecision 决定具体请求。代理对照灯、匿名站点可达、TCP 成功、TLS 正常、历史 DIRECT 连接都不能单独使国内账号上线。

DirectProof 是应用按支持的证据模型签发的短期许可，不是内核提供的物理路由保证。

### 4.2 证明绑定的内容

每份证明至少包含：

| 字段 | 用途 |
|---|---|
| proofId、generation | 关联决策并拒绝旧回调 |
| target | 标准化 host、协议、端口，必要时路径类别 |
| transportScope | 适用的 Chromium 网络路径、进程／入站上下文、配置；不能只有平台 id |
| addressFamily | IPv4／IPv6 的证据范围 |
| ruleEvidence | 当前配置摘要、命中规则及实际策略终点 |
| egressEvidence | 对应通路的出口 IP 地理信息、ASN、来源与时间；完整 IP 留主进程 |
| observedAt、expiresAt | 采样时间和到期时间 |
| exclusions / reason | 无法支持的分支及拒绝原因 |

不能按策略显示名称是否含 DIRECT 来判断；必须确认它实际指向直连策略。回显站证明的是它自己的目标链路，必须说明为什么该出口证据适用于待放行目标，不能将全机单一“国内出口”套到所有目标。

### 4.3 首期放行条件

同时满足以下条件：

1. 目标属于该国内平台审核后的业务、登录、验证码或资源域名范围；域名匹配有完整边界，拒绝未知端口、协议和目标。
2. mihomo 当前配置可读且属于支持模式；针对该目标和实际传输上下文，可以确定当前有效规则的策略终点是 DIRECT。
3. 对应直连通路的匿名出口证据符合中国大陆出口政策，来源有效且无冲突。ASN 用于辅助解释，不用 ASN 注册地代替 IP 地理判断。
4. 适用的匿名 HTTPS 检查通过，证书验证保持开启。TLS 正常只证明连接身份和可达性，不证明直连。
5. DNS、IPv4／IPv6 和实际可能使用的地址族均在证据范围内。fake-IP 单独识别；无法还原必要路由信息就不可验证，不能把保留地址误判为海外。
6. 证明、规则证据、出口证据都未过期，generation 与当前网络版本一致。

“境外解析”可以按产品政策拒绝，但文案使用“目标地址不符合策略／无法核实”，不直接称为 DNS 污染。IPv6 不可验证时，只有确实约束该业务传输使用已验证地址族且完成实验，才能按该地址族运行；否则休眠。

mihomo 支持按进程、域名及网络类型匹配，不能把 Node 探针结果直接套到 Chromium 请求。[mihomo 路由规则](https://wiki.metacubex.one/config/rules/)

### 4.4 如何取得目标证据

首期实现可解释的规则子集，而不是复制整个 mihomo 内核。按真实规则顺序分析目标和上下文，解析必要的规则集与策略链；引用信息不全、进程分支无法确定或规则类型未支持时，返回不可验证。

阶段 2 必须形成支持规则清单和实验记录，证明这些解释与当前内核行为一致。不能假定 /rules 或 /connections 提供了“预测任意未来请求路由”的接口。

/connections 是辅助观测源。使用连接证据时必须关联本次匿名探测及其目标、连接标识和可核实上下文；不能按 host 取第一条别的连接。没有对应连接不等于 DIRECT。历史连接仅供诊断审计，不直接签发新的许可。[mihomo 控制 API](https://wiki.metacubex.one/api/)

### 4.5 有效期与撤销

建议初始参数：本地配置／连接观察 10—15 秒；目标路由许可上限 15 秒；匿名出口检测 60 秒、其证据最多保留 120 秒。最终数值在阶段 2 记录实际成本后冻结，必须保留上限。

运行期间对必要目标在许可到期前主动续证；默认应留出网络响应余量，不能等到 15 秒期限刚过才检查。相同 generation 且目标范围不变的有效续证可平滑替换，无须反复休眠。

许可到期定时器必须主动触发第 6.1 节撤销，不等待下一条 onBeforeRequest 才发现；刷新失败或到期未完成就关闭并中止在途工作。出口证据的较长有效期不能延长目标路由许可。普通设置中的探测间隔不能越过这些限制；不得保留“五分钟前 DIRECT 仍算现在已验证”。

发现模式、有效规则、策略链、网卡、路由、地址族、控制器连接状态变化，或电脑休眠／恢复时，先使相关 generation 失效，再重新验证。无法定位影响范围时关闭全部国内账号。尚未发现的外部变化属于第 1.3 节边界。

休眠恢复的连续两次成功必须来自同一 generation、同一待恢复目标集合／操作范围的不同轮次新采样。建议间隔至少 15 秒；不能拿不同目标各成功一次、跨配置版本或同一份缓存凑次数。失败、配置版本或待恢复范围变化立即清零；历史许可不跨应用重启恢复。

休眠预检期间只记录采样结果，不签发可用于业务的许可；第二次合格后才签发当前许可。运行期间的到期前续证与这组恢复采样分开，避免把正常续证实现成每 15 秒强制休眠。

### 4.6 未知目标先拒绝

账号页面出现新 API、CDN、验证码或重定向目标时，先取消该请求，再安排匿名核验。审核域名策略和路径证据均合格后，重新签发许可。

未知目标不能自动加入永久白名单；需要的业务目标无法证明时，该账号进入等待国内网络。诊断请求限速、合并且不携带原业务 URL 中的凭据。

被取消的 POST、文件上传、二维码确认等操作不通用重放。只有明确可安全恢复的数据任务，才重新申请执行。

## 5. 国内会话、请求与业务入口执法

### 5.1 统一会话工厂

AccountSessionRegistry 统一取得国内账号 Session。任何业务代码接触 session 前，必须完成账号类型检查、幂等守卫安装和网络设置初始化。

替换 AccountService.checkStatus() 无视图时的裸 fromPartition 路径。启动顺序固定为：创建默认拒绝 Gate → 建立会话工厂 → 注册受控业务入口 → 启动巡检和调度。

每个国内 Session 使用 direct 代理模式，并等待设置完成后才可能发业务；初始化或配置变化时处理已有连接，避免复用旧代理连接。这个设置不能绕过 TUN，不能代替 DirectProof。国内 Session 不接受系统／固定代理作为失败回退。

### 5.2 SessionGuard

configureAccountSession() 调用独立的 ensureSessionGuard()。每个 Session 一个主请求监听器，监听器读取当前 Gate，不捕获永久的 true。

onBeforeRequest 对目标逐项判断；任何请求包括没有 webContentsId 的请求都不能默认豁免。覆盖导航、刷新、前进后退、子框架、资源、XHR、fetch、重定向和 WebSocket 握手；后台路径的实际覆盖以实验为准。

现有 navigation-policy 仍负责导航目的地。verificationHosts 是导航许可，不是网络证明豁免；其链路合格时放行，账号休眠时同样拒绝。视频号的微信 CDN 也在对应账号 Session 的执法范围内。

Electron 每种 webRequest 事件只使用最后安装的监听器，因此观察、决策、审计必须由同一入口组合，避免后续模块覆盖门闩。[Electron WebRequest](https://www.electronjs.org/docs/latest/api/web-request)

### 5.3 Session 生命周期

守卫由 Session 注册表持有。隐藏或销毁 view 不卸载门闩；wipeAccountSession() 清存储不等于新建 Session。重复取得、重置、备份替换和视图重建都必须保持默认拒绝与幂等安装。

关闭账号、删除账号和退出应用时，先撤销业务再清理资源；未证明 Session 不再有网络活动前，不留下无守卫窗口。

### 5.4 所有业务入口共享 Gate

| 入口 | 网络不合格时 |
|---|---|
| 新建账号后的登录页、二维码轮询、passport | 不打开远程登录页，不完成电脑侧登录 |
| viewShow、viewGo、navigate、reload、back、forward、内部 load | 拒绝远程动作，显示本地等待界面 |
| checkStatus、启动巡检、Cookie／页面活动触发的探测 | 不发带凭据 probe，不误写登录结论 |
| refreshProfile、account-online 触发的资料采集 | 经统一任务入口等待，不能直接调用 collector 绕过 |
| 定时采集、手动采集、keepalive、登录重试 | 等待或合并，不导航、不采集、不保活 |
| publishOpenUpload、publishAttachFiles | IPC 立即返回 NETWORK_WAITING；附加文件前再次检查 |
| 延迟导航、重试计时器、旧任务回调 | 许可失效即不执行，不触发新的业务 |

允许离线创建本地账号记录；网络不合格时“开始登录”不可用，后续需要用户主动进入登录流程。不自动在网络恢复时弹出登录页或发布页。

工作台的失败处理不能自动打开系统浏览器作为替代国内通路。现有打开外部链接的入口需区分普通帮助链接与国内业务页面。

### 5.5 主进程与页内 fetch

所有带账号会话的主进程探测统一经过 gatedSessionFetch()：发起前授权、绑定撤销信号、异步完成后核验 generation，拒绝返回 GATE_CLOSED／GATE_REVOKED 等专用结果。

Electron 当前文档说明 session.fetch／net.fetch 使用 Chromium 网络栈并触发 webRequest；仍须验证仓库锁定版本的真实取消行为。gatedSessionFetch 无论实验结果如何都保留。[Electron Session fetch](https://www.electronjs.org/docs/latest/api/session#sesfetchinput-init)

pageFetch／pageJson／firstJson 要传递取消语义；不能把门闩撤销吞成 status=0 后继续试候选 URL。各平台数据解析保持原行为，禁止临时改用主进程 fetch 绕过页面收集。

## 6. 运行转休眠与双状态

### 6.1 撤销顺序

1. 原子更新应用内 Gate 为拒绝，递增 generation，禁止新任务出队。
2. 撤销在途任务许可和 AbortSignal，取消延迟探测、重试与导航。
3. 对相关 Session 执行 closeAllConnections()，停止页面加载并处理后台请求来源；保留 Cookie 和登录存储。
4. 将安全数据任务转为 waiting-network；上传中断保留记录并要求用户重新确认。
5. 迟到结果不得将休眠写成 offline／network_error，不得触发 account-online 或继续重试。

closeAllConnections() 文档定义会终止在途请求；不能据此声称所有长连接、上传和后台任务均已实测覆盖。无法通过实验约束的路径必须被禁用或继续关闭相关能力。[Electron 连接终止](https://www.electronjs.org/docs/latest/api/session#sescloseallconnections)

当前隐藏页面继续运行不能当作暂停证据。阶段 2—3 要验证 Service Worker、background-sync、WebSocket、持续上传及页面定时器；必要时关闭远程 WebContents 并显示本地占位，Session 守卫继续保留。不用 wipe 清登录态来实现休眠。

### 6.2 登录状态与网络状态分开

为了兼容仓库，保留 Account.status 字段及现有六态，文档中将它称为 authStatus。另加主进程提供的 AccountNetworkState：

~~~text
state: checking | allowed | dormant
reasonCode / reasonText
generation
checkedAt / proofExpiresAt
requiredTargetSummary
~~~

UI 可以派生 dormant 标签，但数据库中的登录结论不会被 dormant 覆盖。网络状态和历史诊断可以展示，放行资格只在主进程内存中有效。

休眠不刷新 lastCheckedAt、lastOnlineAt 或登录有效期，不发账号掉线通知。offline 表示登录失效，needs_verification 表示验证码；network_error 只用于许可有效时真实业务失败。

### 6.3 恢复顺序

不同轮次匿名检查连续两次合格 → 允许必要的受控登录复核 → 仅对登录有效且符合任务条件的账号恢复数据任务。

网络恢复用单独的事件，不能冒充 account-online。原来 offline／needs_verification 的账号不自动进入采集队列。恢复后每个请求仍需目标许可，不因账号卡变绿而整分区无条件放行。

## 7. 队列、幂等与发布助手

新增国内任务实体 cn_jobs，保持现有 collect_runs 为执行历史、publish_records 为人工发布计划／记录。

建议字段：id、account_id、kind、trigger、state、dedupe_key、created_at、updated_at、attempt_count、reason_code。执行时再绑定 generation，不持久化可复用的网络许可。

状态为 queued、waiting-network、running、done、failed、cancelled。等待网络不是失败，不计入平台限流退避或登录失败统计。

- 提交接口立即返回 taskId、state 和等待原因；进度通过事件或查询返回，取消独立 IPC。
- 定时采集按账号、种类和调度窗口去重；每账号最多保留一次待执行保活，过期保活不逐次补跑。
- 可恢复数据任务按既有并发限制、顺序和抖动执行，不同时冲刷全部账号。
- 删除或重置账号取消对应待执行任务。重启后的 running 先转等待并核验幂等条件，再决定是否可重试。
- 任务队列可以本机持久化，但不随备份导出活跃任务，防止在另一台设备重放操作。

用户的任意导航、进入登录页、打开上传页、附加文件和点击发布，不作为恢复时通用重放的任务。安全采集任务重新执行时，可以在重新授权后导航审核过的 workingUrl。发布助手继续打开官方页、辅助选择文件和人工确认；网络失效时中断，不自动重新挂文件、不自动续传、不自动发布。

人工发布结果无法确认时，保持“待确认／结果未知”，不伪造成功，也不自动重复提交。

## 8. 匿名诊断与四态界面

### 8.1 诊断传输

Chromium 路径检查使用独立非持久诊断 Session，显式 credentials: omit，不复制账号 Cookie／Token，不复用账号页面，不加载携带账号参数的 URL。可达性检查优先轻量 HTTPS 请求。

需要显式代理 Agent 的诊断使用 Node HTTPS 或 Undici dispatcher；不把 Agent 当作 Electron net.fetch 的参数。Node 检查可以显示对照结果，不能独立批准 Chromium 路径。[Node fetch dispatcher](https://nodejs.org/docs/latest/api/globals.html#custom-dispatcher)

诊断无平台 Cookie、平台 Token 或平台 Authorization。访问本机控制器或认证代理所必需的控制器／代理鉴权只在主进程专用通道使用，绝不转发到目标站点；凭据不进入日志。

同一个 mihomo mixed 端口仍可能把国内目标选成 DIRECT。只有确认实际代理链路时才显示“代理可访问”；否则显示“代理入口可达，实际路线未证实”，不能假装有两条独立出口。

公开目标按 host 合并、限速；使用首页或公开连通端点，不打个人信息、作品列表和创作者中心。控制器地址默认限本机 loopback，禁止 URL 内嵌秘密和凭据重定向；首期不支持任意远程控制器。

### 8.2 顶栏四态

四态保留，但代表资格摘要，不冒充物理断网检测。国内按平台、账号及实际目标分别决策，顶栏还必须显示可用数和受限数。

| 国内核心通路有可用资格 | 经验证的国际代理通路可用 | 顶栏 |
|---|---|---|
| 是 | 是 | 双通路 |
| 是 | 否 | 仅国内 |
| 否 | 是 | 仅海外 |
| 否 | 否 | 全断／暂无合格通路 |

例如“双通路 · 国内 4/6 可用，2 个待验证”；不能用一个绿灯掩盖某个平台被规则送代理。代理尚未配置时显示“未配置”，不能写成已经确认海外断网。

账号卡显示：网络状态、具体原因、上次真实登录状态、等待任务数、最近验证时间及到期时间。国内直连灯来自有效资格；代理对照灯只作灰色说明。

建议固定文案：

- 无法验证国内直连，正在等待网络。
- 当前目标不走 DIRECT，严格模式已暂停。
- 当前出口不符合中国大陆策略。
- 登录／验证码相关目标尚未验证。
- 控制器不可读，按不可验证处理。
- 网络证据已过期，正在重新验证。
- 代理可以访问该站，国内业务仍须直连。

设置提供控制器公共地址、凭据配置状态、诊断代理参数、允许范围内的探测间隔和只读严格模式说明。提供可复制的 DIRECT 规则建议，包含所需业务／登录／验证码／资源域名；不只输出 topLevelHosts，也不自动修改用户配置。

阶段 2 顶栏必须标明“观察模式，尚未启用请求拦截”，不能显示已经受到严格保护。

### 8.3 主界面的头像与封面

现有 renderer 的远程头像／封面不经过账号 Session。阶段 3 将其改为主进程受控匿名下载与本地缓存，以不暴露远程签名 URL 的本地标识交给 renderer；可扩展现有 sv-asset 协议。

该下载器同样按目标网络策略判断，休眠只显示缓存或占位。不能简单把远程 URL 转给默认 session.fetch 当作已经受控。补充主界面 CSP 和检查，防止继续直接加载远程图片。

## 9. 代理开启时的扫码登录

~~~text
电脑二维码页、轮询、接收会话 → ClipDock 账号分区 → 电脑实际出口
手机扫描与确认             → 手机自己的网络
电脑登录后的页面、采集、保活 → 同一账号分区 → 电脑实际出口
~~~

手机使用国内网络，不会替电脑侧请求选择国内出口。平台可能分别观察这些请求，本文不推断其内部设备或风控归类。

| 电脑环境 | 工作台行为 |
|---|---|
| 规则模式，登录及依赖目标均 DIRECT，证据合格 | 允许打开登录页和用户扫码 |
| TUN 开启但规则模式路径合格 | 同样可以允许，不因 TUN 开启一律拒绝 |
| global 模式，海外代理能打开页面 | 国内休眠，不打开二维码页和轮询 |
| 任一必要登录目标未知、失联或证据过期 | 等待验证，不能先完成登录再标休眠 |

普通浏览器经海外代理是否能扫码成功由平台决定；“能登上”只表示流程成功，不说明电脑侧是国内直连。

可选记录“本程序首次观测到在线时的出口摘要”，仅作审计。存量空值表示未知，不倒推首次登录地点，不标记所谓永久污染，不建议把重扫作为确定性修复。

## 10. 凭据、备份与审计

### 10.1 CredentialVault

新增凭据表：id、kind、owner_id、ciphertext、encryption_version、created_at、updated_at。Clash secret、代理密码及后续 OAuth token 只由主进程访问。

使用锁定版本可用的 Electron safeStorage 加密；Windows 使用其 DPAPI 支持。保存前检查加密可用性，失败拒绝保存，解密失败保持未配置／休眠，不降级明文、不静默删除原密文。[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)

这是本机存储保护，不声称可以抵御同一 Windows 用户权限下的恶意程序。

公共 AppSettings 只含地址、端口、间隔等字段。账号 Cookie 仍保留在原隔离分区，不搬进主界面或新凭据表。

### 10.2 Renderer 边界

账号 Cookie 和 OAuth Token 不进入应用主界面 renderer；官方账号网页仍按浏览器正常机制使用自己的会话。

设置页允许用户在密码框短暂键入 Clash secret／代理密码，通过专用只写 IPC 提交后清空。输入不进 Zustand、通用 settings、日志、备份；已保存秘密只返回 hasCredential 等元信息。不声称 JavaScript 能保证抹除所有内存副本。

若未来要求输入值也完全不经过 renderer，单独改为主进程凭据导入入口，不用普通 React 密码框满足字面零接触要求。

### 10.3 备份

保留 AES 加密容器；显式定义 BackupAccount、BackupSettings 等 DTO 和完整版本 schema，逐字段构造，不展开生产对象或原样导出 settings。

凭据表及其密文、秘密引用、Cookie、网络放行证明、活跃任务均不进入 BackupPayload。敏感键正则仅为最后断言，不能作为主要边界。

导入同样验证国内平台、字段、关联和版本；未知字段拒绝或由明确版本迁移移除，不直接调用宽松 settings.patch。恢复后 Gate 关闭、网络重新验证、秘密重新配置，不能恢复旧许可。

### 10.4 复用现有 AuditEvent

扩展 NetworkSnapshot、RouteDecision、BlockedRequest、GateRevoked、SchedulerSkip、TaskStateChanged、UploadAttempt、PublishResult；国际阶段再加 OAuthEvent。

统一事件 schema 和脱敏入库：时间、账号／平台、目标 host、审核过的路径模板、请求类型、proofId、generation、原因、取消结果。path 可能含凭据，默认不记录原始 path；不记录 query、fragment、请求体、请求头、Cookie、Token、完整上传 URL。

高频取消按账号、host、原因和时间窗聚合，记录数量和首末时间，避免同步写库风暴。renderer 只收到已脱敏事件。

审计记录被取消不等于证明物理零泄漏，验收必须结合独立接收端和受控网络证据。

## 13. 国内验收矩阵

实验固定为仓库锁定 Electron 版本和 Windows 环境，记录实际版本。先用临时分区、合成 Cookie、受控 HTTPS／代理接收端验证，再在已经确认合格的环境检查真实平台兼容性。不用真实账号向不合格出口发送凭据来测试门闩。

| 场景 | 必须观察到的结果 |
|---|---|
| 启动即 global／控制器不可读 | 生产 Session 首次业务前已经闭闩；无视图巡检也不发 probe |
| 规则模式、目标 DIRECT、证据合格 | 该目标可运行；TUN 开启本身不误判为 global |
| 代理能打开 B 站／抖音，国内证据不合格 | 对照可显示，国内登录／采集仍拒绝 |
| 首页 DIRECT，API／验证码／CDN 走代理 | 未证明目标被拒绝，首页许可不能批准整站 |
| 相同 host 的另一进程有 DIRECT 连接 | 不能借用其连接证据批准 Chromium |
| 未知 host、重定向目标、端口、地址族 | 先取消再匿名验证，无带 Cookie 探路 |
| 证明到期、观察失败、配置变化、电脑恢复 | 许可失效；新任务等待，旧 generation 不继续提交 |
| Electron session.fetch、页内 fetch／XHR | 合成 Cookie 请求在门闩关闭时未到达受控接收端 |
| 子资源、iframe、重定向、隐藏页面 | 同 Session 执法；无缺少 webContentsId 的默认放行 |
| 已建立 WebSocket、上传、Service Worker、background-sync | 撤销后按记录的机制终止／禁用；未覆盖的能力不宣称通过 |
| 手动 profile、启动巡检、account-online、保活、延迟重试 | 全部受同一 Gate 控制，不通过其他入口继续出网 |
| 休眠及迟到回调 | 不误写 offline／network_error，不刷新真实登录验证时间、不弹掉线通知 |
| 连续两次新采样合格 | 才恢复业务资格；原掉线／验证码账号不自动采集 |
| 手动采集等待、长时间休眠、重启 | IPC 及时返回 taskId；任务可取消、去重、有序恢复、不补跑全部保活 |
| 发布打开、附加文件及中途失效 | 前置拒绝／撤销有效；无自动重挂、续传、发布或伪造成功 |
| 隐藏、销毁、重建 view；wipe；备份替换 | Session 守卫不丢失，不复用旧许可 |
| 国际 id 创建、备份导入、异常账号记录 | 被国内模型边界拒绝，不能创建国际分区账号 |
| 秘密、带敏感 path 的 URL、恶意备份字段 | 主界面、公共设置、日志、备份明文／解密 payload 中无禁止数据 |
| 外部在放行后改变路由 | 独立记录检测与撤销窗口；不将窗口描述为绝对零 |
| 既有功能回归 | 分区登录、采集、素材库、人工发布、typecheck、lint、单元测试、Electron 冒烟通过 |

应用审计只证明本程序做了什么；接收端／受控网络记录证明请求是否实际到达。两种证据要可关联，不能单凭零条 BlockedRequest 或零条审计记录认定零外泄。

阶段 2 还需确定证明刷新成本、取消时限与平台域名覆盖。阶段 3 发布前冻结这些数值和已验证的后台路径清单；未验证部分保持拒绝，不留“默认应该没问题”。

## 14. 国际平台独立里程碑

国际部分不与国内阶段 3 捆绑。首期候选为 TikTok 草稿能力、YouTube 读取与上传、X 按已获套餐和权限提供能力；具体 scope、回调要求、审核、配额和费用到该阶段以官方资料与实际应用资格核对，不在国内计划中预设已获许可。

统一能力模型：readProfile、readMetrics、listWorks、uploadVideo、createDraft、publish。无权限就禁用对应能力，不伪造成功，不改爬网页。

OAuth 使用系统浏览器，主进程管理 state、受支持的 PKCE、回调及 Token。loopback 必须是对应平台允许的方式，不支持时先完成合规回调设计，不能虚构所有平台通用的本地授权流程。

Token 交换、刷新、平台 API、分块上传及重定向后的每一跳均经 ProxyTransport。显式 CONNECT 只保证请求交给代理入口，入口仍可能选 DIRECT；必须验证国际策略，直连回退或未验证终点一律拒绝。

白名单按 API、Token、上传目标分别维护；动态上传 URL 作为能力凭据留主进程，每次跳转重新检查，不向不受信任目标转发 Authorization。代理断开取消任务并等待，不能转入 Chromium 或系统 net.fetch 重试。

系统浏览器中的授权网页由系统网络控制，不冒称它也经过 ProxyTransport；若产品进一步要求授权网页全程指定代理，另验该前提，未满足时不开放对应授权入口。

国际追加验收：GlobalAccount 无 partition、无法进入 AccountWorkspace；国内业务误送 ProxyTransport 被拒绝；代理失效无直连回退；权限不足准确禁用；上传／发布结果未知不自动重试造成重复。

## 15. 开始实施时的固定顺序

先记录代码与测试基线，完成国内类型和凭据／备份边界；再实现匿名观察和隔离实验，明确当前支持的规则和证据。

随后将所有业务 Session 收敛到默认闭闩的工厂，接通请求门闩和业务 Gate，再接在途撤销、双状态、队列及发布助手拒绝。最后做六平台兼容性、动态网络变化和全部回归验收。

阶段 3 合格即交付国内严格模式。国际基础设施与平台能力按独立里程碑推进。
