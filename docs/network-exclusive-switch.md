# 国内／海外互斥切换：最新需求补充

2026-09-09，产品目标改为：**rule 模式下按账号和业务目标验证 DIRECT，国内直连与海外代理可以并行；global/TUN 或证据不完整时继续安全休眠。** 当前正式入口仍以互斥 strict 作为默认安全降级，待生产证明源完成接入后才允许 `rule-split`，避免把观察结果误当成直连许可。本机受控实验与真实网络开关验收分别记录，不将它们混为同一结果。

代理客户端窗口打开、进程存在，不单独等于代理已经启用。rule 模式下还必须同时满足逐目标规则命中、直连出口、DNS、IPv4/IPv6 和审核目录证据；任一项读不到、过期或冲突时，该账号保持休眠。global、未验证 TUN 和生产证明源不可用时继续走互斥 strict，不能推定 DIRECT。

| 当前事实                                             | 国内侧                                                     | 海外侧                                                            |
| ---------------------------------------------------- | ---------------------------------------------------------- | ----------------------------------------------------------------- |
| 系统代理、TUN 均明确关闭，连续两次稳定且国内网络可用 | 可恢复出网；账号仍需满足原登录状态与任务条件               | 休眠                                                              |
| rule + 国内目标全部验证为 DIRECT + 海外代理有效       | 国内账号逐账号允许登录、采集、保活和上传助手；其他账号仍可休眠 | 进入海外模式；只有代理可用、官方 API 已接入且账号已授权，才可运行 |
| global、未验证 TUN、未知规则或任一国内目标非 DIRECT    | 国内账号立即休眠；包括登录页、扫码轮询、采集、探测、保活和上传助手 | 进入海外模式；只有代理可用、官方 API 已接入且账号已授权，才可运行 |
| 两者均关闭但网络不可用                               | 等待国内网络                                               | 休眠                                                              |
| 启用状态未知或正在切换                               | `checking`，闭闩，不运行                                   | 不宣称已就绪或已运行                                              |

这里“海外苏醒”表示切换到海外使用条件，不是伪造国际业务成功。国外网页登录入口和可选官方 API 已接入主进程；真实平台授权、登录和业务数据仍需用户提供账号或开发者应用后验收。界面不能因为检测到代理开启就显示账号已登录或业务成功。网页和 API 都继续使用主进程受控代理通路，代理不可用时休眠，不能回落直连。

保留已有的主进程执法与状态边界：

- 开启代理或发现状态失效时先闭国内 Gate、撤销许可，阻止新任务；请求守卫覆盖账号 Session，调度器停止采集、保活及登录探测，导航和发布助手入口直接返回等待原因。
- 撤销在途 lease、取消页面／主进程请求并关闭连接；旧回调不能写回 online、刷新验证时间或重新入队。国内任务保留为等待状态，发布助手仍由用户确认，不在恢复后自动重新挂文件或发布。
- 登录轴与网络轴继续分离：数据库 `status` 保留登录结论，网络休眠只改变内存中的 `AccountNetworkState`。不清 Cookie、不要求因网络切换重扫，不弹“账号掉线”。
- 代理关闭后，系统代理与 TUN 的关闭状态必须连续两次稳定，国内网络确认可用后才恢复资格；只恢复符合登录条件的待执行任务，不能自动为 offline 账号创建采集。
- 重启默认 `checking`，等待主进程新投影。renderer 不持久化网络允许状态；Cookie、Token、代理秘密仍不进备份、日志或 renderer 读取接口，凭据不可安全加密时拒绝保存。

新实现的验收围绕实际切换：只打开客户端 UI 而未启用代理不应被误当成开启；系统代理或 TUN 开启均应阻断国内新请求并取消在途工作；关闭后不足两次稳定检查不恢复；未知状态不亮绿；网络切换不改登录结论或真正验证时间。国外窗口、API 授权和平台登录状态分别显示，代理开启不冒充已登录。

## 本次接线与检测范围

- `windows-proxy-state.ts` 读取当前 Windows 用户系统代理、PAC、自动发现及活动隧道路由；当前已读到的 mihomo TUN=true 也是关闭国内的正证据。关闭控制器本身不会强制国内休眠，仍以独立 Windows 读取为准；代理端口可以连接、客户端进程存在都不等于系统代理开启。
- `exclusive-switch.ts` 是当前默认安全降级策略来源。已知代理关闭且 OS 网络指纹稳定后，才调用无 Cookie 的 Chromium 回显与地域查询；两次独立 CN 成功、间隔至少 10 秒后允许国内。`rule-split` 的生产证明接入后将由逐目标 Gate 取代总闸；在此之前不得仅凭观察到的 DIRECT 放行。每次探测后再次读取代理状态；旧读数、到期、网络变化、休眠或新的 TUN 正证据先撤销所有租约。
- 当前默认：Windows 状态每 5 秒读取一次、读数最长 15 秒有效；出口通常每 60 秒更新、最多保留 120 秒，前两次恢复各做新采样。已读到 TUN 开启不等待下一轮 OS 读取就撤销；未被程序观测到的外部切换仍存在采样窗口，不承诺物理原子切换或零包。
- `runtime.ts` 复用原请求钩子、初始化、在途清理、调度器和任务租约。互斥模式不创建旧的 per-host 路径资格；`rule-split` 只有在审核目录、证明源和逐目标 Gate 全部就绪时才可选用。代理关闭时保留原导航白名单和正常子资源行为；未知或失败时按账号撤销许可。旧策略代码仍保留用于受控实验，生产默认保持安全降级。
- 顶栏改为国内模式／代理模式／检查中／网络不可用，隐藏原 DIRECT 规则配置工作流。网络状态只留内存，按 `switching` 的真实截止时间降级；国外网页和 API 的代理验证、授权及登录状态分别显示。
