# 生产 DirectProof 的最小可运行证据政策

日期：2026-09-08（Asia/Shanghai，跨午夜复核）。依据：[冻结规格](./严格分流方案-合并定稿.md)第 1、4、5、13 节。本附录澄清证据政策，不修改冻结架构，不表示本机已满足签发条件；本轮没有修改配置、业务源码或启用 strict，没有使用真实账号。

## 1. 决定：先验证当前配置，不要求用户先换网络

当前规则模式可以作为首个生产配置候选。每个业务目标仍须取得当前有序规则结论，但出口样本可以在**有明确适用性依据的同一直连通路类**内共享。不要求逐目标架设公网来源回显，不要求每次续证都有一条可关联的 `/connections`，也不要求运行二进制能与公开源码完整对应。

此前 [证据研究报告](./network-stage2-proof-issuer-evidence.md)第 6—7 节的源码身份、逐连接关联和固定接口建议，属于取证方法或收窄政策，不能全部升级成冻结规格的必备前提。本附录以冻结规格为准解释这些建议；原实验事实不变。

| 分类 | 保留或调整的要求 |
|---|---|
| 规格硬要求 | 目标/协议/端口、实际传输上下文、generation、短有效期、当前规则实际终点为直连、适用的大陆出口证据、TLS/DNS/所有可能地址族、双次新采样、变化先撤销 |
| 合理首期政策 | 审核精确域名；仅支持可解释的当前规则前缀；已验收的 Chromium/TUN 路径；使用可信大陆上网链路；先限制为已验证的传输协议；证据出现冲突即拒绝 |
| 不是硬要求 | 完整官方源码可追溯、每个目标公网回显、每轮每目标 socket 归因、每个 Session 使用相同 OS PID、只能使用名为 DIRECT 的出站、必须固定网卡或关闭整机 IPv6 |

同一 NIC 本身不够。共享依据必须包括实际直连出站、地址族、目的地址对应的接口/路由选择和代际；不能把“本机曾测到一个国内 IP”发给所有目标。支持范围也明确假定所选大陆上网链路没有另一个按目标转往海外的上游代理；存在此类网关或有矛盾观测时，应拆分通路类或拒绝。这里采用规格第 1.3 节允许的观察信任模型，不要求证明互联网每个上游设备的内部状态。

## 2. 两种可执行配置选择

### A. 保留当前规则 + TUN，按现有直连通路签发（优先）

本轮只读控制器确认：`rule`、TUN 开启、`gVisor`、`auto-route=true`、`auto-detect-interface=true`、全局 `ipv6=false`；全局接口字段为空，`/proxies/DIRECT` 实际 `type=Direct`。其中 `interface` 和 `dialer-proxy` **均实际存在且为 String 空字符串**，不是缺失字段补默认值；`id` 存在且非空，`ip-version` 字段则确实缺失。这里不输出原始配置或秘密。

实现时把当前已审核目标的早期精确 DOMAIN 规则解释为目标路由证据，确认其在任何未决分支之前直接结束；回显目标也须独立完成同样的规则检查。两者通向同一个已核实的直连出站，且实际接口/路由/地址族属于同一类时，才引用该类的新鲜匿名出口样本。

空接口字段不是自动不合格。可以用当前 OS 路由、接口身份与真实匿名连接的出站观测，验证当前内核自动接口选择的符合性，绑定该配置/内核生命周期；自动选择变化由 generation 撤销覆盖。不能仅用路由哈希推导实际接口，亦不能把 TUN 的 fake-IP socket 地址当物理出站。

当前物理以太网存在非 link-local IPv6 地址和 IPv6 默认路由。因此 `ipv6=false` 或一次 IPv4 成功不能直接推出“所有业务只可能 IPv4”。A 有两种合格结论：

- 当前真实路径可使用两族：同一操作范围的每个目标必须获得两族对应通路证据，请求检查执行 AND；无须在 onBeforeRequest 猜当前选族。
- 已通过锁定有效配置和 IPv6-only/双栈/重试负向实验验证实际直连仅可 IPv4：保存这个路径约束的证据及适用范围，才能按 IPv4 签发；改变约束立即失效。不能仅凭若干成功样本宣称约束成立。

**A 不要求现在改用户网络。** 当前数据尚未完成上述出口适用性和地址族验证，故尚不能签发；这与“当前环境原则上无法实现”不同。若 A 所需字段可读且符合性实验通过，直接交付 A，不再追加配置门槛。

### B. A 的地址族/接口约束无法核实时，再收窄直连出站

维护一个实际 `type: direct` 的出站，显式指定 `ip-version: ipv4`、经用户选择的大陆物理接口、无 `dialer-proxy`，将审核目标及回显目标指向该出站。账号 Session 仍使用 `setProxy({mode:'direct'})`，TUN 仍由 mihomo 处理；这是约束 mihomo 的直连拨号，不是 Electron 绕过 TUN。

官方文档支持上述 Direct 字段，且 `ipv4` 与 `ipv4-prefer` 不同，后者不能当单族约束。[Direct 配置](https://wiki.metacubex.one/en/config/proxies/direct/)、[通用字段](https://wiki.metacubex.one/en/config/proxies/)

这是备选配置设计，**本轮未应用，也未验证 424c2ef 对这些字段的行为**。需要读取运行出站元数据、核对已加载的相关配置并进行正反向实验；API 不暴露的字段不能从名称或一次连接补写。有效配置的加载/重载必须可识别并使原符合性结果失效。若这个构建确实不支持所需行为，再选择兼容内核；“找不到官方对应源码”本身不构成必须换内核的理由。

支持命名直连时按实际类型/终点检查，不将它误判为代理，也不能因名字带 Direct 放行。若首期仅验收 TCP，需在 Chromium 中确实限制 QUIC 并完成实验；不能只给类型填 `tcp`，也不能把 Direct 的 `udp` 字段当作已验收的全面 UDP 禁止。

## 3. issuer 的具体输入来源

| 输入 | 来源与约束 |
|---|---|
| `kernelEpoch/configVersion/rulesVersion` | 主进程读取运行控制器、模式、当前规则、实际策略类型/链、相关配置；结合内核进程生命周期与 OS 网络代际。读不到即失效；公开版本字符串不是完整身份。 |
| `transportProfile` | 统一 Session 工厂的真实 contextId、已完成 direct 初始化/旧连接清理、锁定 Electron 路径验收、Network Service 生命周期及 TUN 入站/DNS 方式。诊断 context 和账号 context 分开保存。 |
| `targetRuleEvidence` | 对该规范 host/protocol/port/network 运行当前有序规则解释，保存规则索引、来源版本、实际直连终点和上下文适用理由。早期 DOMAIN 已结束时，后面的 PROCESS/GEO 条件不再决定该目标，不能反过来要求这些无效分支提供字段。 |
| `dnsAndFamilies` | 当前内核 DNS/fake-IP 可解释结果与已验证的有效出站选族策略，结合必要实际拨号观测。`/dns/query` 是输入之一，不独自证明 Chromium 请求最终选族；未知默认包含所有可能族。 |
| `targetTlsEvidence` | 审核后的匿名轻请求，在适用路径上验证证书和目标身份，不带原业务 query、Cookie、认证或用户数据；无重定向借证。 |
| `egressClassEvidence` | 对该直连通路类的匿名 HTTPS 回显，保存本次来源 IP、真实采样时间、可信地理来源和辅助 ASN。选已有公开服务即可，不要求用户有服务器，也不要求服务实现专用随机数回显协议。禁止缓存响应当新样本。 |
| `applicabilityEvidence` | 当前目标和回显目标分别命中同一个实际直连出站；该出站选择的物理接口/路由类/AF一致；没有未决目标特有覆盖；当前业务 transportProfile 位于已验收范围。必须保存这些引用及论证版本，不能只传一个 true。 |
| `currentConnectionObservation`（可选） | 无歧义 socket + 当前 `/connections` 关联，作为路径符合性、实际拨号 AF/IP 和矛盾检查来源。使用时保留真实来源；没有必要字段就不用此证据来源，不能借别人的连接或填补内核空 process。 |

出口通路类建议键为：`kernelEpoch + effectiveDirectPolicy + physicalRouteClass + addressFamily + osNetworkGeneration`。`physicalRouteClass` 包括目的地址对应的路由选择，不能只是网卡名称。某个目标落入其他接口/路由或有独立出站覆盖，就应分出另一类并另取样本。

业务与诊断不需要伪装成同一个 Session。路径适用性来自二者各自的实际上下文及当前规则的等价结论：若精确 DOMAIN 在进程分支前结束，可明确证明此规则选择不依赖进程；若有效分支确实依赖进程/入站，则必须补齐各自上下文，不能用另一个进程的 DIRECT 样本代替。即便规则等价，DNS、接口、协议与地址族仍须匹配。

## 4. 对现有核心的最小模型调整建议

不是把连接验证器放宽，而是区分证明来源：

```ts
type RouteEvidenceSource =
  | { kind: 'current-ordered-rules'; ruleIndex: number;
      effectiveOutboundId: string; contextApplicabilityId: string }
  | { kind: 'correlated-current-connection'; connectionId: string;
      correlationEvidenceId: string };
```

两种来源仍必须携带相同的目标、上下文、generation、当前规则版本及单调采样时间。当前核心的“每目标必填 connectionId/correlationVerified/chains=['DIRECT']”是实现选择，规格第 4.4 节没有要求；应新增有来源的规则证明，不能造一个连接 ID 通过旧断言。连接 reader 继续只生成路由观察，不负责把观察升级成 TLS、DNS 或出口证明。

按操作需要生成审核目标范围，不把尚未使用、已过时或未知的整个平台域名清单强行并入每一次读操作许可。读取、登录、上传分别预检各自必要范围；页面出现范围外请求仍拒绝。固定读取范围先合格可以运行该读取操作，不等于整个登录/上传流程已验收。

两次恢复采样继续是同一范围、同一 generation 的两个新轮次。规则/路径与必要目标检查不得用旧缓存冒充第二次；较长有效期的出口证据可以按冻结规格被两轮引用，但不更改其采样时间。主动到期撤销、续证合并和失联处理不变。

## 5. 最少外部条件与当前结论

方案 A 首先只需要已有控制器访问、既有审核域名规则、可访问的匿名回显/地理来源，以及可确认属于受支持大陆上网链路的物理出口。不要求用户提供整份含秘密配置、购买服务器、安装驱动、切换 TUN 或提前配置命名直连。仅对当前 API 未暴露且影响路径的配置项，需要在主进程读取其有效配置的必要字段，不能把缺项猜成默认值。

只有 A 的实际验证失败且失败确实源于无法确定的接口/选族政策，才使用 B，所需用户信息至多是选定大陆物理接口并允许维护这小段出站和域名规则。没有网络设置能把真正的海外直连出口“证明成大陆”；若两族样本确实海外、规则含未决分支或路径有矛盾，继续休眠。

当前可以继续实施 **A 的有来源规则证明 + 通路类适用性检查 + 分操作目录**。尚缺的是这些具体验证结果和 issuer 接线，不是全套源码审计或逐目标自建回显。这一结论不授权用历史诊断直接设置 `applicabilityVerified=true`，也不宣称当前已可开启 strict。

## 6. 本机 API 可见版本的实际边界

本轮 `/configs` 返回 38 个顶层字段。仅记录相关字段的存在性和计数，不记录配置值、代理信息或 URL：

| 字段/结构 | 实际返回 |
|---|---|
| `dns`、`hosts` | 均缺失 |
| `rules`、`rule-providers`、`proxy-providers`、`proxies`、`proxy-groups` | 均缺失（`/rules` 是另一接口） |
| `sniffer` / `sniffing` | 前者缺失，后者存在；不能当完整嗅探配置 |
| `ipv6`、`interface-name`、`tun` | 均存在 |
| 顶层 `dns-hijack` / `tun.dns-hijack` | 前者缺失；后者存在，数组 1 项 |
| `geodata-mode`、`geodata-loader`、`geosite-matcher` | 均存在 |
| `geo-auto-update`、`geo-update-interval`、`geox-url` | 均存在，`geox-url` 结构有 4 个属性；不等于运行 geo 数据内容/版本 |

初次复核时 `ClashReader` 仅对 `/configs + /rules + /version` 的实际响应计算哈希。2026-09-08 00:18 的实现已加入 `/proxies/DIRECT` 稳定策略元数据，只有 alive/history 健康统计不参与版本；任一接口失联使当前读取失败。它**仍不能据此称为完整有效配置、DNS/hosts 内容或 provider 版本**；即使哈希稳定，也不能保证未暴露字段没有热更新。

issuer 应分别命名和保存 `visibleControllerVersion` 与按需取得的 `effectivePathPolicyVersion`。对于早期 DOMAIN 已结束的目标，不必为无效的后续 GEO/RULE-SET 分支取得全库内容；但实际影响该路径的 DNS、hosts、出站策略仍需要其有效输入来源及变化边界。可读取本机当前有效配置的必要字段/加载代际，或使用确实能提供这些版本的运行 API；不输出整配置，也不把一个 DNS 回答当配置版本。字段缺失时只将受影响的路径判为未核实，不能给所有未知字段补默认值。

## 7. 核心来源模型已调整

`live-rule-evidence.ts` 已实现 `createLiveRuleEvidence()`：实际解释本轮有序规则，绑定目标、上下文、代际、内核和真实 Direct 策略，校验独立路径记录、可能地址族及短期有效性。原连接来源仍保留源连接校验，规则来源不能伪造连接 ID 混入。构造器不生成出口/TLS/DNS 证明，也不自行采集路径适用性；生产签发器仍待完成。

Runtime 已支持默认同时检查 IPv4 与 IPv6 的精确请求目标；只有所有可能分支合格才允许。只有调用方提供实际验证过的族解析器时，才使用它确定的单族；返回空值、异常或错目标一律拒绝。这个修改解除“没有当前族字段就永久不能运行”的实现限制，没有把未知族默认成 IPv4。
