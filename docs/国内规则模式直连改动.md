# 国内规则模式直连

> 历史记录：本页方案曾在 2026-09-10 被代理开关互斥策略替代。2026-09-12 用户重新要求国内外同时使用，最新实现见[规则模式国内外同时使用](规则模式国内外同时使用-20260912.md)，不再让国内网页依赖本页的短期地理探测许可。

本次仅实现第一项需求：代理开启且处于规则模式时，国内平台可以在已验证的中国大陆 DIRECT 通路上运行，海外继续使用原有的独立代理验证。

## 运行方式

- 代理关闭：保留原有的国内网络检查和恢复流程。
- 规则模式：主进程匿名验证 DIRECT 出口为中国大陆，再为各国内账号配置独立的本机 CONNECT 中转端口。Cookie、LocalStorage 和登录分区继续独立保存。
- 每条官网连接都核对 mihomo 实际连接记录、Windows 接收套接字与进程归属、目标、DIRECT 适配器及当前网络版本。验证通过后才转发浏览器 TLS 数据；没有直连回退或 TLS 解密。
- 全局模式、控制器不可读、非 DIRECT、出口不符或证据失效时暂停。网络恢复后重建连接，当前页面自动重试打开，原错误提示随成功打开清除；不会自动重发发布操作。
- 此版本验证实际 IPv4 目的地址。未验证的 IPv6 和明文 HTTP 请求不作为国内可用通路。

## 修复的具体问题

1. 生产入口此前使用“代理开即休眠”的互斥开关，没有接入规则模式的国内业务通路。
2. CONNECT 成功并不代表内核路由记录立即可读。国内核验现在等待连接归属检查后再读取实际路由。
3. 国内页面大量并发资源导致 Windows 查询启动成本和续检排队。新增有界后台查询进程，每次读取新证据；匿名出口续检与网页资源使用不同的查询通道。原证据有效期不延长。
4. 一条连接关闭不再等待其他页面连接的核验完成，避免占满连接槽位。
5. 国内页面关闭非代理 WebRTC UDP；原有 QUIC 禁用和账号分区保护继续生效。
6. 网络恢复时前端重新打开当前账号页面，并清除过期的打开失败提示。

## 实机记录

2026-09-10，在本机 Windows、Electron 43.3.0、mihomo TUN 开启的环境下：

- 全局模式下国内匿名探测拒绝放行。
- 用户切换规则模式后，匿名 DIRECT 探测确认 CN/IPv4。
- 六个平台的官网入口均通过实际 DIRECT 和 TLS 验证：抖音、快手、小红书、哔哩哔哩返回 200；百家号返回 302；微信视频号对匿名 HEAD 返回 405（连接和 TLS 成功，405 不是登录成功）。
- 在独立测试分区打开小红书完整官方登录页，页面可显示，出口许可在页面加载和续检期间保持有效。

相关诊断脚本位于 `scripts/electron-domestic-direct-egress-probe.mjs`、`scripts/domestic-web-live-direct-probe.mjs` 和 `scripts/domestic-page-live-direct-probe.mjs`，需要显式传入 `--run-once`。记录在 `docs/.compare` 与 `docs/domestic-direct-egress.*.results.json`。诊断没有使用用户账号、提交验证码或更改代理配置。

官网入口与匿名登录页验证不能代替全部平台的登录、上传、发布和长时间在线验收。网络许可表示通路符合策略，不表示平台已确认账号登录；部分附加资源仍可能因连接容量、路由或证据不足而被拒绝。

## 使用

交付检查：141 个测试文件、4106 项全量测试通过；最后的并发与续检调整另通过 52 项针对性测试。类型检查、生产构建和 Windows 打包通过。使用 `--packaged --require-domestic-direct` 在临时数据目录启动打包程序，实测生产入口进入 CN DIRECT 双通路状态，并跨续检周期保持同一许可代次；凭据加密与原有海外功能边界检查也通过。

使用重新构建的 `release/win-unpacked/短视频矩阵工作台.exe`。保持代理规则模式，确保本机控制器地址、端口和密钥正确。网络栏显示“规则双通路”或“双通路”后，国内账号会按当前通路恢复；单个站点若仍不走 DIRECT，需要检查该站点在代理客户端中的规则命中情况。
