# 本机国际应用配置

入口：**国外平台 → 官方 API（可选）→ 开发者应用配置**，或**设置**中的同一配置面板。账号创建和分类不要求开发者应用，独立网页登录环境从国外账号侧边栏直接进入对应平台官网。尚未申请开发者应用时保留“未配置”即可，不需要填写示例 ID，也不需要改系统代理或 TUN。

| 平台    | 本机填写                               | 回调端口                                     | 应用密钥                       |
| ------- | -------------------------------------- | -------------------------------------------- | ------------------------------ |
| YouTube | Google OAuth Client ID，桌面应用类型   | `0` 表示授权时选取空闲端口，也可填写固定端口 | 可选；官方提供时可加密保存     |
| TikTok  | Desktop Login Kit 的 Client Key        | 固定端口，1024–65535                         | 需要 Client Secret             |
| X       | OAuth 2.0 Native／公共应用的 Client ID | 固定端口，1024–65535                         | 此接入类型不使用 Client Secret |

回调路径固定为 `/oauth/callback`。固定端口对应 `http://127.0.0.1:端口/oauth/callback`；请将实际地址登记在相应开发者平台。Google 动态端口显示的是格式说明，不能把 `<动态端口>` 原样当成真实地址。修改端口时也要核对开发者平台登记。

申请准备可参考官方资料：Google 需为项目启用所需 API 并创建 OAuth 客户端，桌面授权使用系统浏览器和 loopback 回调。[Google 原生应用 OAuth](https://developers.google.com/identity/protocols/oauth2/native-app)；TikTok 使用 Desktop Login Kit 的应用信息及登记的重定向地址。[TikTok Desktop Login Kit](https://developers.tiktok.com/doc/login-kit-desktop/)；X 使用 OAuth 2.0 PKCE 的 Client ID，不要把 OAuth 1.0 API Key 当成它。[X OAuth 2.0 PKCE](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code)

密码框只用于本次提交，保存、失败或关闭后清空。旧密钥不会回填；同一 Client ID 下留空表示保留已有密钥，换成另一个 Client ID 时不会沿用旧应用密钥。TikTok 更换应用时必须同时填写新密钥。

“清除密钥”保留公共配置，但会清掉该平台保存的账号 Token，并要求重新授权。修改客户端身份、端口或密钥也会使旧授权失效，其他平台不受影响。加密不可用时拒绝保存秘密；数据目录复制到另一电脑或 Windows 用户后，如密钥无法解密，需在本机重新填写。

“配置已保存”只表示本机字段及必要密钥已保存，不代表应用已通过平台审核、账号已授权或代理链路已验证。

本机配置和主动授权入口现已接入。在账号记录上点击“官方授权”后，主进程先检查应用配置、秘密是否可用以及当前代理证据；合格才打开系统浏览器接收官方授权。打开页面或保存配置不会自动启动授权。流程中可点击“取消授权”；取消停止本次流程，不等于撤销平台上已经完成的授权。浏览器预览不能发起真实授权。

授权后可点击“读取数据”，立即提交可取消的读取任务，资料、指标及最多 20 条作品保存为本机快照。代理尚未合格时任务等待，离开页面不会取消，重启后先重新检查；只有已主动提交的任务会恢复。打开页面只查询本机快照与任务记录。主进程在本次读取需要时刷新 Token，刷新不了或权限失效会明确提示，不自动重新打开授权浏览器。详见[读取范围](global-read-adapter.md)、[Token 刷新合同](oauth-refresh-contract.md)和[任务队列](global-jobs-delivery.md)。

TikTok 的普通“官方授权”仅申请 `user.info.basic`；“授权草稿上传”另行申请 `video.upload`。应用和用户实际授予后，才可从素材库提交到 TikTok 收件箱，再由用户编辑并确认发布。统计所需 `user.info.stats`、作品列表所需 `video.list` 尚未申请，界面显示缺少授权范围，不发对应请求。填写应用密钥、刷新 Token 或修改本机字段都不能补齐这些权限。详见[TikTok 草稿实现与边界](global-tiktok-draft-delivery.md)。

YouTube 点击“授权视频上传”才追加 `youtube.upload`，普通“官方授权”保留读取范围。随后选择本地视频并填写信息，默认私密，儿童受众和需披露的合成内容由用户明确选择；实际权限及可见性以平台结果为准。原任务可按服务器确认位置恢复，取消后查询不会重新发送文件。详见[YouTube 上传实现与边界](global-youtube-upload-delivery.md)。

当前没有真实开发者应用或真实平台授权、读取、上传验收。未验证、过期或无法关联的代理路径会拒绝，不根据“代理模式”放行。读取、TikTok 草稿及 YouTube 上传队列已接入，X 上传和平台侧远端撤销尚未完成。此前“授权尚未开放”“读取未开放”“上传未开放”描述的是各自生产接线前的阶段，真实平台使用仍待验收。
