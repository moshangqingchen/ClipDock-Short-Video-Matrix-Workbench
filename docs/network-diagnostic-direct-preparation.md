## 真实应用分支的防护

脚本复用已经明确选定的本机客户端解码器，不自动猜密文/密钥。保持 source 明文与协议材料仅在内存，不输出完整配置、节点、订阅、密钥或 controller 响应正文。控制器固定为已使用的 loopback 地址；API 路径和方法白名单，不允许任意 URL 或重定向。

应用前重新验证当前文件与有序规则、共同可见配置、TUN，以及 rule 模式。要求当前源文件已包含和运行态一致的 TUN；不会像初次改造时额外补入猜测默认值。格式不支持、重复/缺失规则范围导致不可解释、当前模式变化或控制器失联均停止。

只向首个 IP 规则前插入尚缺的两条。两个精确规则若已经存在且全部可解释，应用模式也返回 `ALREADY_CONFIGURED_NO_WRITE`；不会重复添加。原规则文本与其它配置字节保持不变，只插入需要的新行。

`--apply` 才会在原密文同目录创建唯一命名的加密备份和临时密文，并检查 round-trip、备份/暂存字节及路径边界。写前再次比较文件字节、文件身份/修改时间和完整捕获的 live 配置、规则、版本、DIRECT 元数据，再执行同目录替换。DIRECT 健康统计 alive/history 不作为配置；写前 CAS 仍包含实例 id，以识别并发重载。

主动重载/恢复后要求全部规则等于预期有序序列、live `/configs` 完整等于之前的配置、版本和 DIRECT 路由政策保持一致，同时重新解释两个诊断目标及原 30 个候选。仅在这个预期重载比较中将 DIRECT 实例 id 变化单列，保留前后 id 摘要；其它政策差异继续拒绝，并输出差异字段名。没有从生产 Controller 指纹中移除 id，也没有放宽写前 CAS。预期写入字段与文件不同、真实政策变化或校验失败，不能报成功。

写入后失败会恢复备份密文，并重新加载旧文件、必要时恢复捕获的 live 配置，再验证文件和运行状态两边都还原。重载超时也按可能已生效处理，不仅恢复密文就结束。若检测到外部已经替换文件，不覆盖它，明确报告回滚不完整及保留的加密备份/暂存文件名。没有删除用户文件或处理之前被拒绝清理的目录。

文件检查、控制器检查、替换和外部内核不是原子事务；CAS 缩小并检测可见并发变化，不能消除另一个控制者在检查后立刻修改的窗口。该边界与冻结的观察模型一致，不能称物理零窗口。
