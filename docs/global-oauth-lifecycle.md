# 国际授权生命周期实施记录

2026-09-08。本机应用配置、主动官方授权、取消、本地解除，以及手动官方读取、本地快照和按需 Token 刷新已接入桌面主进程及界面。用户尚无开发者应用，没有完成真实账号授权、Token 刷新或平台读取验收，不能据接线完成宣称平台可用。

## 已接入桌面程序

“官方授权”按钮仅在用户主动点击时调用 UUID IPC。主进程组合 `GlobalProxyRuntime`、`OAuthCodeExchanger`、`GlobalOAuthService` 和系统浏览器打开函数；缺少应用或可用秘密时先拒绝，取得当前代理证据后才建立回调监听并交给系统浏览器。浏览器预览明确禁用真实授权。

界面显示等待用户确认、兑换、完成、取消或固定失败原因。授权事件只保存在挂载页面的内存中；完成事件须重新核对主进程当前事务，再刷新账号记录。取消后迟到的开始响应、旧事务事件或已卸载页面回调不能恢复旧授权显示。`state` 查询和打开账号页面不会自动发起授权。

国际账号存在授权记录或需要重新授权时，可选择“清除本机授权”。确认后由专用 UUID IPC 删除该账号的 OAuth 密文、清除远端身份，将授权状态设为未授权，保留名称、平台与本机账号记录。返回值只有公开账号字段。操作不需要密文可解，因此便携迁移后也能主动清理本机旧授权。

此操作不调用平台撤销 API，不宣称平台侧已解除授权。界面及 `OAuthEvent` 明确区分本地清理与远端撤销。数据库操作与审计同一事务，删除／更新／审计失败或者被 SQLite 静默忽略时整体回滚；其他账号及应用密钥不受影响。

## 已完成的授权组合模块

`GlobalOAuthService` 组合真实 `OAuthFlowManager`、应用配置仓库、凭据可用性与配置摘要核验、`GlobalTokenStore` 同步提交。必须显式注入国际资格来源、经代理的兑换器和系统浏览器打开函数，没有默认直连或浏览器回退。

流程先验证国际 UUID、应用配置、Token 加密能力和必需应用密钥，再取得当前国际资格，随后才创建 loopback 接收器和交给系统浏览器。应用身份、密文、账号存在性或资格代际变化时，旧流程不再允许兑换或提交。应用配置更改、账号删除和本地清除入口已经接入先撤销流程、再修改数据库的同步钩子；网络、代理配置、凭据和休眠变化也会撤销对应资格。

UI 投影只有账号／平台／事务 ID、阶段和固定错误码，不包含授权 URL、state、code、PKCE verifier、Token 或秘密。总超时从准入开始计算，包含取得资格、打开浏览器和兑换阶段。取消和过期立即撤销，但并发槽及退出等待会保留到真实底层 Promise、监听器和连接完成清理，不把忽略取消的依赖当作已经停止。

`OAuthCodeExchanger` 实现三平台官方授权码兑换及最小身份确认。每次使用两个通过注入 `ProxyTransport` 发出的请求：Token 兑换、当前频道／用户身份。HTTP 200 仍须满足响应格式、Bearer 类型、有效期、必需 scope 和唯一远端身份；不合格不提交，期间撤销不会把迟到 Token 写入数据库。平台差异和官方来源见[兑换契约](oauth-exchange-contract.md)。

Token 提交补强了实际数据库写入核验：密文需能回读为本次 envelope，授权 UPDATE 和审计 INSERT 必须实际生效，事务末再次核对账号和 Token。已授权旧记录即使值看起来相同，也不能掩盖本次写入被 `RAISE(IGNORE)` 拒绝。

`GlobalReadService` 已将按需刷新接入手动读取流程：接近到期且存在刷新凭据时，经同一代理资格调用 `OAuthTokenRefresher`，再以原 Token 版本核对后提交轮换；读取页面不会启动后台刷新。刷新不能扩大 scope，不可用时显示固定原因，需要重新授权时由用户主动操作。具体期限、轮换和三平台差异见[刷新合同](oauth-refresh-contract.md)。

读取只保存显式公开字段的本机快照，同事务写入不含标题、原响应或秘密的审计。主进程与界面均支持取消；账号、应用或授权版本变化时拒绝旧结果，未返回的数据保留为未知。每次最多 20 条作品，实际能力区分缺 scope、平台拒绝、限流和不可用。当前 TikTok 仅有 basic scope，统计和作品不标可用。详见[读取适配器](global-read-adapter.md)。

## 当前边界

桌面生产入口已经接入授权开始、状态、取消及本地清除，真实代理读取器、匿名出口探针、隧道授权器和官方兑换器也已装配到同一主进程路径。此处描述代码接线；当前真实代理链路、连接归属与出口验证仍在修订，未完成的实测不计为通过，也没有真实平台授权验收。不能因存在 `ProxyTransport` 或连上 mixed 端口，就宣称可以安全发出授权 Token 请求。

`ProxyTunnelReader` 读取指定 loopback 控制器监听身份、mixed 端口本次已接受 socket 的反向四元组及进程身份、同轮配置和当前连接。返回值仍是证据，由 `ProxyTunnelAuthorizer` 核对本次官方目标、socket、内核身份、代际、时间和代理链；读取成功本身不授予出网资格。配置变化、连接歧义、未知链路或失效出口样本都拒绝。不能拿历史连接或另一条匿名连接直接授权业务。具体接口与接线边界见[国际隧道读取与授权](global-proxy-tunnel.md)。

按需 Token 刷新、手动官方读取和能力展示已接入；16:47 新增[持久化读取队列](global-jobs-delivery.md)，迁移 9 的主进程 `grant_revision` 区分新授权与正常刷新，旧任务不能跟随新授权自动执行。上传和远端撤销仍未完成。没有开发者应用不妨碍继续实现，但真实授权、刷新和读取验收必须由官方配置、实际权限和真实路径证据支持。此前将刷新与读取列为待实现的结论属于这些模块接线前的阶段。
